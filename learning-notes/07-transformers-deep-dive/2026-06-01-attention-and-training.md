# Transformer 核心概念学习笔记

> 日期: 2026-06-01

## 1. 为什么需要 Transformer

2016 年主流模型是 RNN/LSTM，核心问题是**必须逐步计算**——处理第 t 个 token 时必须等第 t-1 个 token 算完，无法并行。序列越长，等待时间线性增长，且无法用更多 GPU 加速（步骤间有依赖）。

2017 年 Transformer 的自注意力机制允许对序列中所有位置**同时并行计算**，将训练从"串行等待"变成"一次矩阵乘法"，大幅缩短了实际训练的墙钟时间（wall clock time，即挂钟上实际流逝的时间）。

## 2. Softmax

将任意实数向量转换为**概率分布**的函数：

```
softmax(z_i) = e^(z_i) / Σ e^(z_j)
```

- 输出每个元素在 (0, 1) 之间，总和为 1
- 保留大小顺序，放大差异
- 在注意力中用于将分数转为"该关注多少"的权重

## 3. Q、K、V 的含义

每个 token 通过三个投影矩阵生成三个向量：

| 向量 | 含义 | 类比 |
|------|------|------|
| **Q (Query)** | 我在找什么 | 搜索关键词 |
| **K (Key)** | 我包含什么 | 书脊上的标签 |
| **V (Value)** | 被选中后能提供什么 | 书的实际内容 |

K 和 V 为什么要分开？因为"匹配用的特征"和"提取用的内容"可以不同，分开后模型有更大灵活性。

### 是训练涌现的还是人为设定的？

- **人为设定**的是框架：有三条路径，各自做矩阵乘，Q 匹配 K，用结果加权 V
- **训练学到**的是具体含义：Wq、Wk、Wv 矩阵里填什么数值，由模型在数据上自动学出
- "K=我包含什么，V=能提供什么"是训练结果的**事后归纳**，不是事前规定

## 4. Multi-Head Attention（多头注意力）

Head 就是并行跑多组独立的 Q、K、V 计算，每一组叫一个 head。

一个 head 只能学到一种关注模式，而一个词可能同时需要多种关注（语法、位置、语义）。多个 head 各自关注不同东西，最后拼起来。

```
假设 d_model = 512，8 个 head → 每个 head 64 维

head 1: X @ Wq1, X @ Wk1, X @ Wv1 → 64 维
head 2: X @ Wq2, X @ Wk2, X @ Wv2 → 64 维
...
head 8: X @ Wq8, X @ Wk8, X @ Wv8 → 64 维

concat → 512 维 → 乘 Wo → 最终输出
```

每个 head 有独立的 Wq、Wk、Wv，所以能学到不同的关注模式。

## 5. 多头拼接的结果是什么

不是 token，是一个**向量**——该 token 更新后的表示向量。

向量 vs token 的关系：
- **token**：离散的文本单位，如"猫"
- **向量**：token 在模型内部的数值表示，如 [0.23, -0.87, 1.45, ...]

每一层注意力做的是**更新向量的内容**，让它包含更多上下文信息。只有在最后需要输出文字时，才把向量映射回 token。

## 6. 同一 token 在不同层的向量不同

```
第 0 层（embedding）: "它" → 只知道这是个代词
第 1 层: 知道前面有 "猫" 和 "垫子"
第 2 层: 开始偏向 "猫"
第 3 层: 确信 "它" = "猫"
最后一层: 包含完整上下文理解
```

而且同一个 token 在不同句子里的向量也不同（上下文相关表示），这是 Transformer 比 Word2Vec 强的地方。

## 7. 推理时向量仍会变化

训练完后**写死的是权重**（Wq、Wk、Wv 等矩阵），**动态变化的是向量**（每个 token 的表示）。

```
权重 → 菜谱（固定不变）
向量 → 正在做的菜（每次输入不同，结果也不同）
```

推理时虽然不更新权重，但信息仍逐层流动变化——这正是模型能"理解"新输入的原因。

## 8. 参数 = 权重 = 数字

一整个模型有**一套固定权重**，所有 token 共用同一套 Wq、Wk、Wv。参数、权重、数字是同一件事的三种说法。

```
1.5 亿个参数 = 权重矩阵里总共 1.5 亿个数字 = 模型文件约 300 MB

BERT-base    →  1.1 亿参数   →  约 440 MB
GPT-2        →  15 亿参数    →  约 6 GB
GPT-3        →  1750 亿参数  →  约 350 GB
```

## 9. 语料和权重的关系

语料没有"变成"权重，而是**压缩提取**了语料中的模式。类比：读 100 本书，记不住每句话，但脑子里形成了规律和模式。

模型没有记住任何原文，学到的是语言规律。实际压缩比约 1000:1（几 TB 语料 → 几 GB 模型）。

## 10. 训练三要素：架构、数据、算力

| 要素 | 作用 |
|------|------|
| **架构（参数规模）** | 决定上限：模型最多能学会多少 |
| **数据** | 决定下限：模型实际学到了多少 |
| **算力** | 决定能不能：把前两者变成现实 |

三者的关系：

- 架构大 + 数据少 → 浪费容量
- 数据多 + 架构小 → 装不下，过拟合
- 架构大 + 数据多 + 算力不够 → 根本训练不动

算力不只是"更快"，还是"能不能做"的问题。GPT-3 训练用了约 10,000 张 GPU 跑 34 天，没有这些算力根本跑不了。算力也间接推动架构进化——先有足够算力，才能试出更大的模型确实更强。
