# 多词元预测 (Multi-Token Prediction, MTP)

> 从 GPT-2 到 Llama 3，每个自回归大语言模型在每个位置上都只训练一个损失：预测下一个词元。DeepSeek-V3 在每个位置上增加了一个额外的损失：预测再下一个词元。这些额外的 140 亿参数（在 6710 亿参数的模型上）通过梯度流被蒸馏回主模型，而训练好的 MTP 头部在推理时被重新用作投机解码的草稿生成器，接受率高达 80% 以上。1.8 倍的生成吞吐量几乎是白送的。本节课从零构建 DeepSeek 技术报告中的顺序 MTP 模块，计算损失和共享头部的参数布局，并解释为什么 MTP 保持了因果链，而 Gloeckle 等人提出的原始并行 MTP 却破坏了它。

**类型：** 构建
**语言：** Python (标准库)
**前置知识：** 阶段 10 · 04 (预训练一个迷你 GPT), 阶段 10 · 15 (投机解码)
**时间：** ~60 分钟

## 学习目标

- 阐述 MTP 训练目标并推导跨预测深度的联合损失。
- 解释 Gloeckle 等人 (2024) 的并行 MTP 头部与 DeepSeek-V3 的顺序 MTP 模块之间的区别，以及为什么顺序设计保持了因果链。
- 计算在预训练运行中添加 MTP 模块的参数和内存开销。
- 从零实现一个 MTP 模块：共享嵌入、逐深度的 Transformer 块、投影层和共享输出头部。

## 问题所在

下一个词元预测是标准的大语言模型训练目标。每个隐藏状态只被监督去预测一件事：紧随其后的那个词元。这是一个出奇弱的信号。序列中的大部分信息都延伸到一个词元之外——结构、连贯性、事实性、算术流。模型必须通过数万亿个词元上积累大量单词元信号来学习这些内容。

MTP 提出的问题是：如果每个隐藏状态同时被监督去预测多个未来词元会怎样？Gloeckle 等人 (Meta, 2024) 证明了这是有效的。他们的实现方式是在骨干网络之上放置几个独立的输出头部，每个预测不同的偏移量。并行、简单，但这些头部看到的是相同的隐藏状态，没有任何层次化精炼——而且预测之间不是因果链式的，因此无法用于投机解码。

DeepSeek-V3 (2024 年 12 月) 将 MTP 重新设计为在每个预测深度保持因果链的顺序模块。模型从 `h_i^(0)` 预测 `t+1`，然后从新的隐藏状态 `h_i^(1)` 预测 `t+2`，该状态将 `h_i^(0)` 与 `E(t+1)` 的嵌入相结合，依此类推。每个深度都是其自身的小型 Transformer 块。共享嵌入和共享输出头部使参数开销保持适度。在 DeepSeek-V3 的规模下，在 6710 亿主模型权重之上，MTP 模块额外增加了 140 亿参数。这 2% 的开销换来了更密集的训练信号，以及在推理时现成的投机解码草稿。

本节课从零构建一个 MTP 模块和 D 深度损失。数学很简洁。实现只需 150 行代码。

## 核心概念

### 顺序 MTP 方案

DeepSeek-V3 在主模型之上添加了 `D` 个 MTP 模块。每个模块 `k` (对应 `k = 1..D`) 预测深度 `k` 处的词元——即给定前缀到位置 `i`，预测 `t_{i+k}`。

模块 `k` 包含：

- 一个 Transformer 块 `T_k`，具有自己的注意力层和 MLP。
- 一个投影矩阵 `M_k`，将前一个深度的隐藏状态与下一个深度的真实词元嵌入相结合。
- 共享嵌入 `E` (与主模型相同)。
- 共享输出头部 `Out` (与主模型相同)。

在训练时，对于前缀到位置 `i`，逐深度的隐藏状态为：

```
h_i^(0) = 主模型骨干在位置 i 的输出
h_i^(k) = T_k( M_k * concat(RMSNorm(h_i^(k-1)), RMSNorm(E(t_{i+k}))) )   当 k >= 1
```

逐深度的预测为：

```
logits_{i+k} = Out(h_i^(k-1))   当 k = 1..D
```

逐深度的损失是与真实值 `t_{i+k}` 的交叉熵：

```
L_k = CE(logits_{i+k}, t_{i+k})
```

跨深度的联合损失：

```
L_MTP = (lambda / D) * sum_{k=1..D} L_k
```

`lambda` 是一个小的权重因子——DeepSeek-V3 在训练的前 10% 使用 0.3，之后使用 0.1。总训练损失为 `L_main + L_MTP`。

### 为什么是顺序而非并行

Gloeckle 的原始并行 MTP 有 D 个输出头部，每个直接应用于 `h_i^(0)`。每个头部从相同的骨干隐藏状态预测 `t_{i+k}`。这训练起来没问题，但预测之间没有条件依赖关系。你无法使用 `head_1` 的输出来帮助 `head_2`——头部是并行触发的。

DeepSeek-V3 的顺序设计从 `h_i^(k-1)` 加上实际下一个词元的嵌入 `E(t_{i+k})` 构建 `h_i^(k)`。这保持了因果链：要预测 `t_{i+k+1}`，深度 `k+1` 的模块能看到 `t_{i+k}` 处的内容。这在结构上与自回归解码器消耗自身输出的方式完全相同——使 MTP 模块可以直接用作投机解码的草稿生成器。

在推理时：将 `h_i^(k-1)` 和草拟的 `t_{i+k}` 输入模块 `k+1`，得到 `t_{i+k+1}` 的预测。重复此过程。这正是一个 EAGLE 风格的草稿，使用训练好的 MTP 模块作为草稿网络。DeepSeek-V3 报告第一个 MTP 模块的接受率超过 80%，速度提升约 1.8 倍。

### 参数核算

对于一个隐藏维度为 `h`、词表大小为 `V` 的模型：

- 主模型：数十亿参数，加上一个大小为 `V * h` 的输出头部。
- 共享输出头部：复用主模型的头部。无额外参数。
- 共享嵌入：复用主模型的嵌入。无额外参数。
- 每个 MTP 模块：
  - 投影 `M_k`: `(2h) * h = 2h^2`。
  - Transformer 块 `T_k`: 注意力层 (`4h^2` 对应 MHA) 加上 MLP (SwiGLU 比例 8/3 时通常为 `8h^2`)。每个块约 `12h^2`。

每个模块的额外总参数：`~14h^2`。对于 DeepSeek-V3 的 `h = 7168`，D = 1 个模块：理论上约 `~14 * 7168^2 = ~720M` 参数。DeepSeek-V3 报告为 140 亿——差异主要在于专家层在 MTP 模块中也是 MoE 结构。

### 投机解码的收益

在预训练期间，MTP 模块使训练速度降低约 10%（更多的前向计算，额外的损失）。收益是双重的：

1. 更密集的训练信号。每个隐藏状态看到 D+1 个监督目标。在 DeepSeek-V3 的消融实验中，对 MMLU、GSM8K、MATH、HumanEval 的测量效果：稳定地提升几个百分点。

2. 推理时免费的投机解码草稿。MTP 模块已经训练好来预测接下来的几个词元。重新用作草稿网络后，它提供 80% 以上的接受率。在这个水平上，N=3 或 N=5 的投机解码可带来 1.8 倍吞吐量。10% 的训练时间成本在第一次运行推理时就回本了。

### 与 EAGLE 的关系

EAGLE 在预训练后单独训练一个小型草稿模型。MTP 将草稿融入预训练中。两种方法在接受率上趋同，但通过不同的流程：

| 维度 | EAGLE-3 | MTP (DeepSeek-V3) |
|-----------|---------|------------------|
| 训练时机 | 预训练之后 | 预训练期间 |
| 与现有权重的向后兼容性 | 是 | 否 (需要重新训练) |
| 草稿参数 | 1-2 个 Transformer 层 | 1 个 Transformer 块 + 投影层 |
| 接受率 | 0.88-0.92 | 深度 1 处 0.80+ |
| 超越速度提升的收益 | 仅投机解码 | 更密集的训练信号 + 速度提升 |

## 动手构建

`code/main.py` 端到端构建一个 MTP 模块：共享嵌入、投影层、Transformer 块、共享输出头部。然后在一个短合成序列上计算逐深度的交叉熵损失，并按组件打印参数数量。一个 32 词元的玩具词表使数字保持可读。

### 步骤 1：共享嵌入表

主模型和每个 MTP 模块在每个深度都使用同一个 `vocab_size x hidden` 表。不是第二个副本——就是同一个张量。

### 步骤 2：逐深度组合

```python
def combine(prev_hidden, next_token_embed, M_k):
    # 沿特征维度拼接，然后投影回隐藏维度
    concat = rms_norm(prev_hidden) + rms_norm(next_token_embed)  # 向量加法替代
    projected = matvec(M_k, concat)
    return projected
```

真正的 DeepSeek-V3 将两个 RMSNorm 后的向量拼接为 `[2h]` 并用 `h x 2h` 矩阵投影。玩具版本为了标准库简洁性使用向量加法。

### 步骤 3：深度 k 处的 Transformer 块

自注意力加 MLP。在玩具版本中，一个单层的线性注意力块和一个 SwiGLU MLP 在不使用 numpy 的情况下保持了结构清晰。

### 步骤 4：共享输出头部

复用主模型的输出投影。在词表上的 logits。

### 步骤 5：逐深度损失

softmax(logits) 与偏移 `k` 处真实词元的交叉熵。用 `lambda / D` 缩放因子跨深度聚合。

### 步骤 6：参数核算

打印总参数数量、共享（嵌入、头部）数量和每个模块的额外数量。展示 MTP 额外参数与主模型大小的比例。

## 如何使用

MTP 已集成到 DeepSeek-V3 (2024 年 12 月) 和 DeepSeek-R1 系列中。在推理时：

- DeepSeek 自己的服务栈开箱即用地将 MTP 模块作为投机解码器消费。
- vLLM 和 SGLang 截至 2026 年 4 月已有 DeepSeek-V3 MTP 的集成路径。
- AMD 的 ROCm SGLang 教程展示了一个特定的 MTP 投机解码配置，在 V3 检查点上测得 1.8 倍加速。

何时在新预训练运行中使用 MTP：

- 你控制完整的预训练流水线，并希望储备更密集的训练信号。
- 你知道你将大规模部署模型，并希望免费获得投机解码。
- 你的隐藏维度至少为 4096。在 1B 规模下，开销的伤害大于收益的帮助。

何时不使用：

- 微调现有的预训练稠密模型。MTP 模块没有被训练过。
- 研究中你想要一个干净的基线来比较。MTP 改变了架构。

1. 运行 `code/main.py`。展示随着合成信号增强，逐深度损失单调递减。修改合成数据使用固定模式，并验证深度-1 和深度-2 的损失都收敛。

2. 计算一个稠密 70B 模型（隐藏维度 8192，80 层）在 D=1 MTP 模块时的参数开销。与 DeepSeek-V3 报告的 140 亿开销进行比较。解释为什么 DeepSeek 的数字更高：MTP Transformer 块继承了相同的 MoE 结构，膨胀了每个模块的参数数量。

3. 在玩具版本中实现 D=2：添加第二个 MTP 模块，接收 h^(1) 并预测 `t_{i+2}`。验证联合损失和参数核算与 DeepSeek 论文的公式 19-21 匹配。

4. 将玩具版本切换为并行 MTP (Gloeckle 风格)：在主隐藏状态之上添加 D 个输出头部，每个预测不同的偏移量。在相同合成信号上测量逐深度的损失与顺序版本的比较。顺序版本在 k > 1 时应该产生更低的深度-k 损失，因为它以中间预测为条件。

5. 将训练好的 MTP 模块用作 EAGLE 风格的草稿：在推理时调用模块 k 来提议 `t_{i+k}`。测量这些草稿词元与主模型在留出序列上的预测的接受率。如果你在玩具上达到 50%+，你就复现了 MTP 作为草稿的实证特性。

## 关键术语

| 术语 | 人们的说法 | 实际含义 |
|------|----------------|------------------------|
| MTP 模块 | "额外损失块" | 一个小型 Transformer 块加投影层，预测主模型 `k` 个位置之后的词元 |
| 预测深度 | "哪个偏移量" | 整数 `k`，使得模块 `k` 从前缀到位置 `i` 预测 `t_{i+k}` |
| 并行 MTP | "Gloeckle 风格" | D 个独立头部在相同骨干隐藏状态上，没有条件链 |
| 顺序 MTP | "DeepSeek-V3 风格" | 每个模块以先前深度的隐藏状态加上下一个词元的嵌入为条件；保持因果链 |
| 共享输出头部 | "复用主头部" | MTP 模块调用主模型的 LM 头部，而不是单独的输出投影 |
| 共享嵌入 | "复用主表" | 到处使用相同的词表嵌入表；没有重复参数 |
| 投影矩阵 M_k | "组合隐藏状态 + 下一个词元" | 一个 `h x 2h` 的线性层，将先前的隐藏状态和目标词元嵌入折叠到下一个深度的输入中 |
| 联合损失 L_MTP | "平均额外损失" | 逐深度交叉熵损失的算术平均值，由 `lambda` 缩放 |
| 深度 1 接受率 | "MTP 草稿多准" | D=1 MTP 模块的 top-1 预测等于主模型 top-1 预测的比率；DeepSeek-V3 上为 80%+ |
| Lambda 加权 | "额外损失重要性" | 逐深度缩放因子；DeepSeek-V3 在训练开始时为 0.3，之后为 0.1 |
