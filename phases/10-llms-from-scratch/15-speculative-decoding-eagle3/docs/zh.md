# 投机解码与 EAGLE-3

> 第 7 阶段 · 第 16 课从数学上证明了：Leviathan 拒绝规则精确地保持了验证器（verifier）的分布。本课则从 2026 年生产级投机解码的训练栈视角展开。EAGLE-3 将草稿模型（draft model）从廉价的近似变成了基于验证器自身隐藏状态专门训练的小型网络，并加入了训练时测试循环（training-time test loop），使其训练分布与推理分布对齐。结果：端到端加速 3 倍至 6.5 倍，对话场景下每个词元（token）的接受率超过 0.9，且没有任何分布上的折中。2026 年的每一个生产级推理栈都默认内置了它。

## 学习目标

- 用一句话陈述 Leviathan 定理，并证明投机循环产生的样本与验证器直接采样的样本同分布。
- 梳理从原始投机解码（Leviathan 2023）到 EAGLE、EAGLE-2 再到 EAGLE-3 的两年演进历程，并指出每一步所消除的确切限制。
- 根据接受率 `α` 和草稿-验证器成本比 `c` 计算预期加速比，并为每种场景选择最优的草稿长度 `N`。
- 从零实现完整的投机循环：草稿生成、验证、从残差分布中拒绝采样、拒绝时回滚 KV 缓存、全部接受时发射奖励词元（bonus token）。

## 问题背景

在 70B 模型上进行自回归解码，在 H100 上可能只有每秒 35 个词元（token）的速度。GPU 远未饱和。内存带宽才是瓶颈：每个词元都要从 HBM 加载 70B 的权重，做一次算术运算，然后输出一个浮点数。计算单元大部分时间都在空转。

投机解码将这个问题转化成了一个你真正可以解决的吞吐量问题。一个廉价的草稿模型用 `N` 次小的前向传播提出 `N` 个词元。验证器在前缀加上所有 `N` 个草稿上只运行一次。如果验证器在第 `i` 个位置上的分布与草稿一致（我们将在后面精确地定义这种统计意义上的一致），就接受；否则拒绝，并从残差分布中采样一个修正词元。一次大模型的前向传播最多可以产生 `N+1` 个被接受的词元，而不是一个。

关键的定理来自 Leviathan、Kalman、Matias（ICML 2023）：输出分布与直接从验证器采样得到的分布完全相同。不是近似，是完全相同。这就是投机解码能在生产环境中被接受的全部原因——它是一种纯粹的延迟优化，没有任何质量上的折中。

第 7 阶段 · 第 16 课给了你数学。本课给你的是训练栈。一个好的草稿模型带来的加速比是一个廉价草稿的两倍。EAGLE、EAGLE-2 和 EAGLE-3（Li 等人，2024–2025）将"草稿 = 同一模型的小型版本"变成了一门精确的工程学科。2026 年的生产级推理服务器默认使用 EAGLE-3。

## 核心概念

### 不变量：Leviathan 拒绝采样

设 `p(t)` 为给定某个前缀后草稿模型对下一个词元的分布，`q(t)` 为验证器的分布。从草稿中采样一个词元 `d ~ p`。以概率 `min(1, q(d) / p(d))` 接受。如果被拒绝，则从残差分布 `(q - p)_+ / ||(q - p)_+||_1` 中采样。最终产生的样本服从分布 `q`。无论 `p` 有多差——越差拒绝越频繁——输出始终保持精确。

将 `N` 次这样的调用串联起来，利用验证器在前缀 `+ d_1 + ... + d_N` 上的一次前向传播同时返回 `q_1, q_2, ..., q_{N+1}`。从左到右遍历。在第 `j` 个位置首次拒绝时，从 `residual(q_j, p_j)` 中采样并停止。如果全部接受，则从 `q_{N+1}` 中采样一个奖励词元。

### 什么决定了加速比

设 `α` 为每个草稿词元的期望接受率。设 `c = cost(draft) / cost(verifier)` 为成本比。每个验证器前向传播中被接受的期望词元数为：

```
E[accepted] = (1 - α^(N+1)) / (1 - α)
```

每个被接受词元的期望总墙钟时间为 `(N * c + 1) / E[accepted]`。对 `N` 最小化该式，即可找到最佳点。当 `α = 0.8, c = 0.05` 时：最优 `N` 约为 5–7，加速比为 3.2 倍。当 `α = 0.95, c = 0.02` 时：最优 `N` 约为 8–10，加速比接近 5 倍。

最大的杠杆是 `α`。在固定 `N = 5` 的情况下，将 `α` 从 0.6（原始草稿）提升到 0.9（EAGLE-3），每个验证器前向传播的期望被接受词元数从 2.2 提升到 4.1。在相同的验证器下，吞吐量几乎翻倍。

### 两年演进历程

**原始投机解码（Leviathan，2023）。** 草稿模型是一个同系列独立训练的较小 LLM。容易接入，`α ≈ 0.6`，加速比最多约 2 倍。

**EAGLE-1（Li 等人，2024）。** 草稿是一个微型 Transformer——通常只有一到两层——以验证器最后一层的隐藏状态作为输入，直接预测下一个词元。由于草稿能看到验证器的特征表示，其分布与验证器更接近。`α` 提升到 0.7–0.8。

**EAGLE-2（Li 等人，2024）。** 增加了动态草稿树：不再提出单个长度为 `N` 的序列，而是提出一棵小型候选树，用验证器在一次前向传播中评分（树注意力），然后走最高概率路径。草稿长度变为每步自适应。每条被接受路径上的词元 `α` 超过 0.85。

**EAGLE-3（Li 等人，2025，NeurIPS）。** 两项改进。第一，完全放弃特征预测损失——EAGLE-1/2 训练草稿去匹配验证器的隐藏状态，这限制了数据能带来的收益上限。EAGLE-3 直接训练词元预测。第二，训练时测试（Training-Time Test, TTT）：在草稿训练期间，将草稿自己之前的预测作为输入反馈回去，持续多步，与它在推理时的运行方式一致。这使训练分布和测试分布对齐，阻止了误差累积。实测加速比：对话场景最高 6.5 倍，在 H100 上使用 SGLang 批次大小为 64 时吞吐量提升 38%。

### KV 缓存回滚

验证过程将验证器的 KV 缓存一次性扩展了 `N` 个条目。如果在位置 `j` 发生拒绝，则位置 `j-1` 之后的缓存内容现在都是错误的。两种常见实现：写入临时缓冲区并在接受时提交（vLLM、TensorRT-LLM），或者维护一个物理 KV 缓存加一个逻辑长度并在拒绝时截断。无论哪种方式，回滚成本都是每层每头的字节数，与前向传播成本相比可以忽略不计。

对于 EAGLE-2 的树搜索，验证器使用尊重树拓扑的非因果掩码运行注意力。工程实现比较繁琐，但计算上只是带自定义掩码的标准 flash-attention 调用。

### 2026 年的草稿架构

| 策略 | 草稿类型 | `α` | 加速比 | 训练成本 |
|------|---------|-----|--------|----------|
| 原始投机 | 独立的小型 LLM | 0.55-0.70 | 1.8-2.3 倍 | 无（复用现有小模型） |
| Medusa | 验证器上的额外 LM 头 | 0.65-0.75 | 2-3 倍 | 约 1B SFT 词元 |
| EAGLE-1 | 基于隐藏状态的单层 Transformer | 0.70-0.80 | 2.5-3 倍 | 约 60B 词元 |
| EAGLE-2 | EAGLE-1 + 动态草稿树 | 0.80-0.88 | 3-4 倍 | 约 60B 词元 |
| EAGLE-3 | 多层特征融合 + TTT | 0.88-0.92 | 3.5-6.5 倍 | 约 60-200B 词元 |
| Lookahead | 无草稿（Jacobi 迭代） | N/A | 1.3-1.6 倍 | 无 |

2026 年生产环境：vLLM 和 SGLang 在可用时默认使用 EAGLE-3，否则使用 EAGLE-2。TensorRT-LLM 为 Meta 和 NVIDIA 的公开模型提供了最快的 Medusa 路径。llama.cpp 为 CPU 部署提供原始投机解码。

## 动手实现

参见 `code/main.py`。这是完整的 Leviathan 投机循环，包含所有组件：N 词元草稿、验证器并行传播、逐位置拒绝、残差采样、奖励词元、KV 回滚，以及输出分布与直接从 `q` 采样相匹配的经验验证。

### 第一步：拒绝规则

```python
def accept(q_prob, p_prob, u):
    if p_prob <= 0:
        return True
    return u < min(1.0, q_prob / p_prob)
```

### 第二步：残差分布

```python
def residual(q, p):
    raw = [max(0.0, qi - pi) for qi, pi in zip(q, p)]
    s = sum(raw)
    if s == 0:
        return list(q)
    return [r / s for r in raw]
```

### 第三步：完整的投机步骤

`spec_step` 函数从 `p` 中起草 `N` 个词元，然后在一个并行的 `q` 评估中验证所有词元。对每个草稿词元应用拒绝规则，在首次拒绝时从残差中采样修正。如果全部接受，则从 `q_{N+1}` 中发射一个奖励词元。

### 第四步：KV 回滚簿记

模拟器为每个工作线程跟踪一个逻辑 `kv_length`。接受 `k` 个草稿时，`kv_length += k`。在位置 `j` 拒绝时，缓存虽然已经写到了 `j` 之后，但逻辑长度被设为 `prefix_length + j + 1`——即修正词元之后的一个位置。后续读取截断到逻辑长度。

### 第五步：Leviathan 检验

运行 50,000 次投机步骤。统计被接受词元的经验分布。与 50,000 次直接从 `q` 采样的结果进行比较。卡方统计量应远低于临界值。该定理在实践中成立。

### 第六步：加速比 vs. α

通过以不同幅度将 `p` 从 `q` 扰动来改变草稿质量。测量 `α`，然后绘制每个验证器调用的期望词元数关于 `α` 和 `N` 的函数。代码会打印一个表格，展示 EAGLE-3 级别的草稿质量（`α ≈ 0.9`）如何解锁每个验证器调用 4–5 个词元。

## 实际使用

生产级 `vllm serve` 配合 EAGLE-3：

```bash
vllm serve meta-llama/Llama-3.3-70B-Instruct \
  --speculative-config '{
    "model": "yuhuili/EAGLE3-LLaMA3.3-Instruct-70B",
    "num_speculative_tokens": 5,
    "method": "eagle3"
  }'
```

在 H100 上使用 SGLang 配合 EAGLE-3，批次大小为 64：根据 EAGLE-3 论文，吞吐量约为批次 64 原始解码的 1.38 倍。

何时使用投机解码：

- 任何 p50 延迟比峰值吞吐量更重要的交互式对话工作负载。
- 代码生成和结构化输出（JSON、SQL）。目标分布高度可预测，`α` 高于 0.9。
- 长文本生成（数千词元）。摊销后的加速比持续生效。

何时不使用：

- 非常小的模型（< 3B）。草稿并不比验证器便宜多少。
- 批次为 1 的微型 CPU 部署。草稿模型的内存开销可能不值得。
- 极高温度的创造性采样，`α` 会崩塌。

## 关键术语

| 术语 | 人们怎么说 | 实际含义 |
|------|-----------|---------|
| Leviathan 规则 | "min(1, q over p)" | 以概率 `min(1, q(d)/p(d))` 进行伯努利接受/拒绝，在拒绝时从残差中采样，精确保持验证器分布 |
| 残差分布 | "(q minus p) plus, normalized" | `(q - p)_+` 在零处截断并重新归一化——拒绝时应从中采样的正确分布 |
| 接受率 α | "草稿有多准" | 拒绝规则下的逐词元期望伯努利成功概率；主导所有加速比数学 |
| EAGLE-1 | "隐藏状态草稿" | 以验证器最后一层隐藏状态为条件的微型 Transformer 草稿（Li 等人，2024） |
| EAGLE-2 | "动态草稿树" | EAGLE-1 加上一棵候选延续树，用树注意力在一次验证器传播中评分 |
| EAGLE-3 | "训练时测试" | 放弃特征预测损失，直接训练词元预测，并在训练期间将草稿自己的输出反馈给它 |
| 训练时测试（TTT） | "暴露偏差修复" | 在训练期间自回归地运行草稿，使训练和测试输入分布匹配——计划采样的直接类比 |
| KV 回滚 | "撤销被拒绝的草稿" | 在拒绝后将验证器的 KV 缓存重置为已接受前缀长度的簿记操作 |
| 奖励词元 | "免费的那个" | 当全部 `N` 个草稿都被接受时，从 `q_{N+1}` 中额外采样一个词元，不增加验证器成本 |
| 树注意力 | "同时验证多个候选" | 使用尊重草稿树拓扑的非因果掩码的注意力；在一次前向传播中计算树中每个节点的 `q_i` |
