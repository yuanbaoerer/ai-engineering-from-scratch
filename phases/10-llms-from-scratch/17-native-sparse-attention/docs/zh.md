# 原生稀疏注意力 (Native Sparse Attention, DeepSeek NSA)

> 在 64k 词元 (token) 的上下文中，注意力机制消耗了 70-80% 的解码延迟。每个开源模型实验室都有计划来解决这个问题。DeepSeek 的 NSA（ACL 2025 最佳论文）是最终落地的方案：三条并行的注意力分支——压缩的粗粒度词元、选择性保留的细粒度词元，以及用于局部上下文的滑动窗口——通过可学习的门控 (gate) 进行组合。它与硬件对齐（对内核友好）、原生可训练（适用于预训练，而非仅在推理时嫁接），并且在 64k 解码长度下运行速度超过 FlashAttention，同时达到或超越全注意力的质量。本节课将端到端构建这三条分支，并解释为什么这种稀疏性是可端到端微分的。

**类型:** 构建
**语言:** Python (标准库)
**前置知识:** Phase 7 · 12 (KV 缓存, FlashAttention), Phase 7 · 15 (注意力变体), Phase 10 · 16 (差分注意力)
**时间:** ~60 分钟

## 学习目标

- 说出 NSA 的三条注意力分支及其各自捕获的信息。
- 解释为什么 NSA 是"原生可训练的"，而此前的稀疏注意力方法仅限于推理阶段。
- 计算在 64k 上下文下，NSA 与全注意力相比的计算节省量，表示为压缩块大小和选择 top-k 的函数。
- 在标准库 Python 中对一个短合成序列实现三分支组合，并验证门控权重的行为。

## 问题背景

全注意力在序列长度 N 下的时间复杂度为 `O(N^2)`，每层 KV 缓存为 `O(N)`。在 64k 词元下，计算量和内存带宽开销是灾难性的。根据 NSA 论文的理论估算：在 64k 长度下，注意力占总解码延迟的 70-80%。下游所有指标——首词元时间 (TTFT)、每秒词元数、百万词元成本——都被注意力成本所主导。

稀疏注意力是显而易见的答案。此前的尝试分为两类。固定模式稀疏（滑动窗口、步长、块局部）会丢弃信息，在长程召回任务上失败。推理时稀疏（KV 缓存剪枝、H2O、StreamingLLM）应用于在密集注意力上预训练的模型，只能恢复一部分潜在加速，因为模型从未被要求通过稀疏模式来路由信息。

原生稀疏注意力 (Native Sparse Attention, Yuan 等人，DeepSeek + 北大 + 华盛顿大学，ACL 2025 最佳论文，arXiv:2502.11089) 兼顾了两者：一种在预训练期间由模型学习的稀疏模式，以与内核对齐的算法实现，在推理时真正交付计算节省。两年后，NSA 或其直接后继者将成为每个前沿长上下文模型的默认注意力机制。

## 核心概念

### 三条并行分支

对于每个查询 (query)，NSA 运行三次注意力，分别针对 KV 缓存的三个不同视图：

1. **压缩分支 (Compressed branch)。** 词元被分组为大小为 `l` 的块（通常为 32 或 64）。每个块通过一个小型可学习的 MLP 压缩为单个摘要词元。查询在这些压缩词元上进行注意力计算，获得整个序列的粗粒度视图。

2. **选择分支 (Selected branch)。** 利用压缩分支的注意力分数，识别出与当前查询最相关的 top-k 个块。读取这些块中的细粒度（未压缩）词元，查询对它们全部进行注意力计算。可以将压缩分支的注意力视为选择的"路由信号"。

3. **滑动窗口分支 (Sliding-window branch)。** 查询对最近的 `W` 个词元（通常为 512）进行注意力计算以获取局部上下文。该分支捕获其他两个分支可能遗漏的结构密集型短程模式（语法、局部共指）。

三个分支的输出通过可学习的逐位置门控进行组合：

```
out = g_cmp * out_cmp + g_sel * out_sel + g_win * out_win
```

`g_cmp, g_sel, g_win` 是来自查询上的小型 MLP 的门控权重。它们不必求和为 1——可以独立地为各分支赋权。

### 为什么这是"原生可训练的"

选择步骤（top-k 个块）是离散的。离散操作会破坏梯度流。此前的稀疏注意力工作要么跳过选择步骤的反向传播（限制了训练），要么使用在推理时无法提供真正稀疏性的连续松弛方法。

NSA 巧妙地规避了这一点：压缩分支的注意力本身就是对整个序列的可微粗粒度注意力。top-k 操作只是复用压缩分支的最高注意力分数来决定加载哪些细粒度块。梯度通过压缩分支的分数流动（这些分数同时影响压缩输出和选择逻辑），而被选中的块对最终输出的贡献也是可微的。不可微的 `top_k` 操作在前向计算图中是一个无操作 (no-op)——它仅控制从内存加载哪些块。

这就是 NSA 能够端到端用于预训练的原因。模型学习将信息联合路由通过三个分支，产生一种在推理时真正兑现承诺加速的稀疏模式。

### 硬件对齐的内核

NSA 的内核是为现代 GPU 内存层次结构设计的。内核按 GQA 组加载查询（外循环），为每组获取相应的稀疏 KV 块（内循环），并在 SRAM 上运行注意力计算。因为每个查询组看到的是相同的选择块（选择是按查询组而非按查询头进行的），KV 加载在组内被摊销。算术强度保持高位。

论文报告称，在 64k 解码长度下，Triton 内核比 FlashAttention 快 9 倍，且加速比随序列长度增长而增长。前向和反向内核均已提供。

### 计算预算

设 `N` 为序列长度，`l` 为压缩块大小，`k` 为 top-k 选择数量，`w` 为滑动窗口大小，`b` 为选择块大小（通常等于 `l`）。

- 压缩分支：每个查询 `O(N/l)` 个键，总计 `O(N * N / l)`。
- 选择分支：每个查询 `O(k * b)` 个键，总计 `O(N * k * b)`。
- 滑动分支：每个查询 `O(w)` 个键，总计 `O(N * w)`。

总计：`O(N * (N/l + k*b + w))`。

当 `N = 64k, l = 64, k = 16, b = 64, w = 512` 时：每个查询的成本为 `1000 + 1024 + 512 = 2536` 个键。全注意力为 `64000` 个键。**计算量减少 25 倍。**

当 `N = 128k, l = 64, k = 16, b = 64, w = 512` 时：每个查询的成本为 `2000 + 1024 + 512 = 3536` 个键。全注意力为 `128000` 个键。**减少 36 倍。** 收益随序列长度增长而增长，这正是其意义所在。

### 与其他方法的对比

| 方法 | 可微分 | 真正的推理加速 | 长程召回 |
|--------|---------------|----------------------|-------------------|
| 仅滑动窗口 | 是 | 是 | 失败 |
| 步长 / 块稀疏 | 是 | 是 | 部分 |
| KV 剪枝 (H2O, StreamingLLM) | 不适用 (推理时) | 是 | 部分 |
| MoBA (Moonshot) | 部分 | 是 | 良好 |
| NSA | 是 (原生) | 是 (64k 下 9 倍) | 匹配全注意力 |

MoBA (Moonshot, arXiv:2502.13189) 是同期发表的工作，采用了类似的"三合一优于单一"思路，将 MoE 原理应用于注意力块。NSA 和 MoBA 是 2026 年长上下文预训练需要了解的两种架构。

## 动手构建

`code/main.py` 在短合成序列上实现了三个分支，并展示了：

- 压缩 MLP（为教学清晰起见使用简单的均值池化基线；真正的 NSA 使用可学习的 MLP）。
- 由压缩分支分数驱动的 top-k 块选择。
- 对最后 `w` 个词元的滑动窗口注意力。
- 门控组合。
- 与全注意力相比的计算量统计输出。

### 步骤 1：将词元压缩成块

```python
def compress(K, l):
    n = len(K)
    n_blocks = (n + l - 1) // l
    out = []
    for b in range(n_blocks):
        start, end = b * l, min((b + 1) * l, n)
        block = K[start:end]
        summary = [sum(row[d] for row in block) / len(block) for d in range(len(K[0]))]
        out.append(summary)
    return out
```

### 步骤 2：压缩分支注意力

对查询运行针对压缩键的 softmax 注意力。压缩分支的分数同时作为 top-k 选择的信号。

### 步骤 3：top-k 块选择

选取 `k` 个得分最高的压缩块的索引。从这些块加载原始未压缩词元并对它们运行注意力。

### 步骤 4：滑动窗口注意力

取最后 `w` 个词元并对它们运行标准注意力。

### 步骤 5：门控 + 组合

查询上的小型 MLP 产生三个门控权重。最终输出是三个分支输出的加权和。

### 步骤 6：计算量统计

打印每个分支每个查询所注意的键数量及总计。与 `N`（全注意力）进行比较。在 1024 词元的合成数据上，使用 `l = 32, k = 4, w = 128`，NSA 每个查询看到 `32 + 128 + 128 = 288` 个键，而全注意力为 1024 个——**减少 3.5 倍。**

## 实际应用

NSA 已应用于 DeepSeek 自身的长上下文预训练管线。截至 2026 年 4 月，公共推理栈中的集成状态：

- **DeepSeek 内部**: 原生支持，发布的权重使用 NSA 或其后继者 DSA (Deepseek Sparse Attention)。
- **vLLM**: 针对 DeepSeek-V3.x 权重的实验性 NSA 支持正在开发中。
- **SGLang**: 已发布 NSA 基准测试；生产路径跟随 vLLM。
- **llama.cpp / CPU**: 不支持；内核分解的开销在 CPU 吞吐量下不划算。

何时选择 NSA：

- 针对 64k+ 上下文、拥有严肃计算预算的预训练或继续训练运行。
- 推理 DeepSeek 自身的长上下文检查点。这些权重是 NSA 原生的。

何时不选择：

- 服务现有的密集注意力预训练模型。没有继续训练无法将 NSA 嫁接上去。
- 上下文低于 16k。三分支的开销压倒了节省。
- 批次为 1 的交互式聊天。延迟敏感的解码虽有收益，但仅在长上下文下。

## 关键术语

| 术语 | 人们怎么说 | 实际含义 |
|------|----------------|------------------------|
| 压缩分支 (Compressed branch) | "粗粒度视图" | 对块平均键的注意力，以每个查询 O(N/l) 个键提供全局上下文 |
| 选择分支 (Selected branch) | "Top-k 块" | 对压缩分支分数最高的 `k` 个块进行细粒度注意力 |
| 滑动窗口 (Sliding window) | "局部上下文" | 对最后 `W` 个词元的注意力，用于短程模式 |
| 原生可训练性 (Native trainability) | "预训练时开启稀疏性" | 稀疏模式在预训练期间学习，而非在推理时嫁接 |
| 压缩块大小 l | "粗粒度视图的分组大小" | 多少个词元合并为一个摘要；典型值 32-64 |
| Top-k | "保留的块" | 读取其未压缩词元的压缩块数量；典型值 16 |
| 滑动窗口 W | "局部注意力半径" | 通常为 512；更短损害局部连贯性，更长浪费计算 |
| 分支门控 (Branch gate) | "如何混合三者" | 逐位置 MLP 输出，为三个分支的贡献赋权 |
| 硬件对齐 (Hardware alignment) | "内核友好的稀疏性" | 选择稀疏模式使得实际 GPU 内核能达到理论加速 |
| DSA | "NSA 的后继者" | Deepseek Sparse Attention，DeepSeek 系列中接替 NSA 的架构 |
