根据任务形态（单答案/多答案/开放式）、token 预算和可用评估器（标量测试/启发式/自评），输出搜索策略推荐及具体参数。

输出内容：

1. **决策**。从以下策略中选择一个：线性 ReAct、束搜索 ToT（束宽 k）、BFS ToT（最大深度）、带剪枝的 DFS ToT、MCTS LATS（迭代次数与 UCT c）、进化搜索（仅当评估器可编程且可检验时）。
2. **参数**。为每个策略给出具体数值默认值：束宽、深度上限、分支因子 K、每层展开次数、UCT c（默认 1.4）、超时时间。
3. **价值函数**。明确指定如何为节点打分。选项：单元测试通过率、与目标的数值距离、通过提示 LLM 打分（sure/likely/impossible 或 1..10 或投票）、环境奖励。
4. **Token 预算估算**。最坏情况 token 数 = 分支因子 ^ 深度 × 平均 prompt token 数。展示该数值。若超出用户预算，推荐更经济的策略。
5. **失败模式**。针对每个选定策略，列出前两大失败模式及缓解措施（例如 LATS + 噪声评估器 → 按 CRITIC 课程 05 的建议添加工具校验）。

硬性拒绝条件：

- 评估器不可靠时（仅自评，无真实标签）推荐搜索。应回退至 ReAct + CRITIC。
- 分支因子 K 设为大于 5 且无充分理由。K=3-5 为论文默认值；K=10 会使成本爆炸。
- 对聊天类任务使用 LATS。搜索对无程序化目标的对话问答无帮助。
- 无机器可检验适应度的进化搜索。AlphaEvolve 仅在适应度可编程时（运行测试、测量速度、验证定理）才有意义。

拒绝规则：

- 若 token 预算 < 单条轨迹成本的 5 倍，拒绝搜索并推荐 ReAct + Reflexion（课程 03）。
- 若墙钟延迟预算 < 10 秒，拒绝 LATS 并推荐 ReAct。
- 若任务为纯信息检索，拒绝搜索并推荐 ReWOO（课程 02）。

输出格式：推荐块（选定策略、参数、价值函数、预算估算）加"下一步阅读"说明，指向课程 05（CRITIC）了解评估器可靠性、课程 11（AlphaEvolve）了解进化变体，或课程 30（评估驱动开发）了解基准级验证。
