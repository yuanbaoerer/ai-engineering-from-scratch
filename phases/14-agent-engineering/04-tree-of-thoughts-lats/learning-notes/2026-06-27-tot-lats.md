# 思维树（ToT）与 LATS 学习笔记

> 日期: 2026-06-27

## 1. 为什么需要搜索：线性推理没有回头路

思维链（CoT）是一条**直线**走到底，第一步选错则后续每步都建立在错误前提上，无法恢复。Game of 24 任务（用 4 个数字通过 `+ − × ÷` 凑 24）是经典反例：

- GPT-4 用 CoT 准确率仅 **4%**
- ToT 提升到 **74%**

真实推理需要的能力：提出多个候选 → 评估 → 选有希望的分支 → 死胡同时回溯。这就是搜索。ToT 和 LATS 是两种经典表述。

## 2. ToT 的核心支撑是自我评估

ToT（Yao 2023）把推理建模成树：

| 要素 | 含义 |
|------|------|
| 节点 | 一个连贯的中间思维步骤 |
| 边 | 展开成 K 个子思维 |
| 价值 | LLM 通过提示做**自我评估** |
| 搜索 | BFS / DFS / beam search 遍历 |

自评的三种形式：`sure/likely/impossible` 分类、`1..10` 数值评分、候选投票。

**关键洞察**：自我评估是 ToT 的核心支撑。没有可靠的节点评分，树搜索就退化成盲目展开。

## 3. LATS 统一 ToT + ReAct + Reflexion

LATS（Zhou 2024）在 MCTS 框架下统一三种技术，让 LLM 同时扮演三个角色：

| 角色 | 对应技术 | 作用 |
|------|---------|------|
| 策略 Policy | ReAct | 提出候选下一步行动 |
| 价值函数 Value | ToT 自评 | 对部分轨迹评分 |
| 自我反思器 Reflector | Reflexion | 失败时写自然语言反思，重设后续 rollout 起点 |

LATS 比 ToT 多两层：**环境反馈**（工具真实结果，非仅模型判断）融入价值函数；**失败反思**驱动下一轮搜索。论文结果：HumanEval pass@1 **92.7%**（GPT-4，当时 SOTA）。

## 4. MCTS 四阶段与 UCT

每次迭代四阶段，顺序固定：**选择 → 展开 → 模拟 → 回溯**。

UCT 公式：`Q(s,a) + c·√(ln N(s) / N(s,a))`

- 第一项 Q = **利用**（选历史均值高的）
- 第二项 = **探索**（访问次数少的给机会）
- `c` 是探索常数，需按任务调（默认 1.4）

## 5. 最重要的反直觉点：噪声评估器让搜索更差

搜索不创造正确性，它只**放大**评估器的判断。当任务只有一个正确答案、但评估器有噪声（如只有 LLM 自评、无 ground truth）时：

> 搜索会找到一个"高分"的错误答案，结果比单条轨迹更差。

这是本课最关键的工程直觉：**评估器质量 = 搜索上限**。搜索会把评分虚高的错误答案一路推到根。因此决策规则要求"评估器不可靠 → 回退 ReAct + CRITIC"。

## 6. 成本现实：搜索是奢侈品

搜索会急剧增加 token 消耗 —— ToT 在 Game of 24 上是 CoT 的 **100–1000 倍**。搜索应保留给：

- 单条轨迹明显不够的任务（复杂数学、代码生成）
- 正确性 > 运行时间
- 有**廉价可靠价值函数**（单元测试、显式数学目标）

2026 年生产现状：大多数生产 agent **并不**跑 LATS，而是跑**带工具验证的 ReAct**（CRITIC，第 05 课）。搜索通过 `if task_complexity > threshold: use_search()` 门控触发。

## 7. stdlib 与代码实现定位

`stdlib` = Python **标准库**（standard library），自带模块，无需 `pip install`。本课 [code/main.py](../code/main.py) 用 `itertools / math / random / dataclasses` 五个 stdlib 模块实现，**零外部依赖、不调 LLM**。

价值函数用**符号距离**（离 24 有多远）代替论文里的 LLM 提示评分，目的是教学隔离：纯粹看懂 MCTS 的选择/展开/模拟/回溯，不被 API 调用与 prompt 工程干扰。

## 8. 代码关键函数解读

| 函数 | 作用 |
|------|------|
| `value()` [main.py:68](../code/main.py#L68) | 符号价值函数：等于 24 返回 1.0，否则返回 `-距离/100` |
| `expand()` [main.py:50](../code/main.py#L50) | 任选两数 + 四种运算，合并成新数，生成所有子节点 |
| `tot_bfs()` [main.py:76](../code/main.py#L76) | ToT 的 BFS：逐层展开 → 打分排序 → 只留 top-8 → 找到正解早停 |
| `mcts()` [main.py:122](../code/main.py#L122) | LATS 的 MCTS：80 次迭代，选/展/模/回，最后取最优叶子 |

**`tot_bfs` 的三个设计**：逐层 BFS（非 DFS）、打分剪枝（beam width=8，保留 top-k）、早停（value>0.99 立即返回）。

**实际运行对比**（干净价值函数下）：
- ToT BFS → `6*4=24, 4-1=3, 24+3=27`（value=-0.030，**未找到正解**，beam 剪枝丢了正确分支）
- LATS MCTS → `6*4=24, 24*1=24`（value=0.000，**找到正解**）

教学点：即使干净价值函数，BFS 的贪心剪枝也会丢正解；MCTS 的探索-利用平衡反而找到。噪声会让这种剪枝错误更频繁。

## 9. 决策规则硬性拒绝条件

来自 [outputs/skill-search-policy.md](../outputs/skill-search-policy.md)，遇到以下情况**拒绝搜索**，回退 ReAct(+Reflexion/CRITIC)：

- 评估器不可靠（只有自评、无 ground truth）
- token 预算 < 5× 单轨迹成本
- 延迟预算 < 10 秒
- 纯信息检索任务 → 用 ReWOO（第 02 课）
- 聊天式 Q&A（无程序化目标）

分支因子 K 默认 3–5，K>5 需充分理由，K=10 成本爆炸。

## 10. 测验错题反思（6/8）

本次测验 4 道概念题全对，2 道实践题错在同一盲点 —— **搜索的成本与可靠性约束**：

| 错题 | 错因 |
|------|------|
| Q5（噪声评估器时搜索结果）| 误选"结果更好"，正确是"结果更差"——搜索放大噪声 |
| Q7（预算 <5× 单轨迹）| 误选"仍上 LATS"，正确是"回退 ReAct+Reflexion"——搜索 100-1000× 成本 |

两题指向同一主题：掌握"搜索是什么"后，还需加强"什么时候不该用搜索"。
