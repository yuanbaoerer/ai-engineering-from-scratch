# Reflexion：语言强化学习

> 基于梯度的强化学习需要数千次试验和 GPU 集群才能修复一个失败模式。Reflexion（Shinn 等人，NeurIPS 2023）通过自然语言实现了这一点：每次失败试验后，智能体写下一段反思，将其存储在情景记忆中，并在下一次试验中使用该记忆进行条件约束。这就是 Letta 的睡眠时计算、Claude Code 的 CLAUDE.md 经验教训以及 pro-workflow 的 learn-rule 背后的模式。

**类型：** 构建
**语言：** Python（标准库）
**前置要求：** 阶段 14 · 01（智能体循环），阶段 14 · 02（ReWOO）
**时间：** 约 60 分钟

## 学习目标

- 命名 Reflexion 的三个组件（Actor、Evaluator、Self-Reflector）以及情景记忆的作用。
- 使用二元评估器、反思缓冲区和全新重试来实现标准库 Reflexion 循环。
- 在给定任务中选择标量、启发式或自评估反馈源。
- 解释为什么语言强化能捕获基于梯度的 RL 需要数千次试验才能修复的错误。

## 问题

智能体在任务中失败。在标准 RL 中，你需要运行数千次试验，计算梯度，更新权重。这很昂贵、缓慢，而且大多数生产智能体没有为每次失败分配训练预算。

Reflexion（Shinn 等人，arXiv:2303.11366）提出了一个不同的问题：如果智能体只是思考为什么失败，然后带着这个想法重试呢？不需要权重更新，不需要梯度。只需要在试验之间存储自然语言。

结果：在 ALFWorld 上，它击败了 ReAct 和其他未经过微调的基线。在 HotpotQA 上，它比 ReAct 有所改进。在代码生成（HumanEval/MBPP）上，它达到了当时的最新水平。所有这些都没有进行一次梯度步骤。

## 概念

### 三个组件

```
Actor         : 生成轨迹（ReAct 风格循环）
Evaluator     : 对轨迹进行评分——二元、启发式或自评估
Self-Reflector: 对失败进行自然语言反思
```

加上一个数据结构：

```
情景记忆：先前反思的列表，预先添加到下一次试验的提示中
```

一次试验运行 Actor。Evaluator 对其进行评分。如果分数较低，Self-Reflector 会产生反思（“我选择了错误的工具，因为我把问题误解为询问 X，而实际上是询问 Y”）。反思被放入情景记忆。下一次试验从头开始，但能看到反思。

### 三种评估器类型

1. **标量**——外部二元信号。ALFWorld 成功或失败。HumanEval 测试通过或失败。最简单，信号最强。
2. **启发式**——预定义的失败特征。“如果智能体连续两次产生相同的动作，则标记为卡住。”“如果轨迹超过 50 步，则标记为低效。”
3. **自评估**——LLM 为自己的轨迹评分。当没有真实标签可用时需要。信号较弱；与基于工具的验证（第 05 课 - CRITIC）配合良好。

2026 年的默认设置是混合使用：可用时使用标量，不可用时使用自评估，启发式作为安全护栏。

### 为什么这具有泛化性

Reflexion 不是一种新算法，而是一种命名模式。几乎每个生产中的“自愈”智能体都运行某种变体：

- Letta 的睡眠时计算（第 08 课）：一个单独的智能体对过去的对话进行反思，并写入内存块。
- Claude Code 的 `CLAUDE.md` / “保存记忆”模式：反思被捕获为经验教训，并预先添加到未来的会话中。
- pro-workflow 的 `/learn-rule` 命令：更正被捕获为显式规则。
- LangGraph 的反思节点：一个节点对输出进行评分，并在需要时路由到细化。

所有这些都源于相同的洞察：自然语言是一种足够丰富的媒介，可以在运行之间传递“我从失败中学到的东西”。

### 何时有效，何时无效

Reflexion 在以下情况下有效：

- 存在明确的失败信号（测试失败、工具错误、错误答案）。
- 任务类是可重现的（可以再次询问相同类型的问题）。
- 反思有足够的空间来改进轨迹（足够的操作预算）。

Reflexion 在以下情况下没有帮助：

- 智能体第一次就成功了。
- 失败是外部的（网络中断、工具损坏）——对“网络中断”进行反思对未来的运行没有帮助。
- 反思变成了迷信——存储了一次偶然失败的叙述。

2026 年的陷阱：记忆腐烂。反思会累积；有些已过时或错误；随着情景缓冲区的增长，重新运行会变慢。缓解措施：定期压缩（第 06 课）、对反思设置 TTL 或使用单独的睡眠时清理智能体（Letta）。

## 构建它

`code/main.py` 在一个玩具谜题上实现了 Reflexion：生成一个和为目标值的 3 元素列表。Actor 发出候选列表；Evaluator 检查总和；Self-Reflector 写下一行关于错误原因的描述。反思被放入情景记忆，供下一次试验使用。

组件：

- `Actor`——一个脚本策略，当它看到反思时会改进。
- `Evaluator.binary()`——对目标总和进行通过/失败检查。
- `SelfReflector`——生成失败的一行诊断。
- `EpisodicMemory`——一个具有 TTL 语义的有界列表。

运行它：

```
python3 code/main.py
```

跟踪显示三次试验。试验 1 失败，存储反思，试验 2 看到反思并改进但仍然失败，试验 3 成功。与基线运行（无反思）比较——它停留在试验 1 的答案上。

## 使用它

LangGraph 将反思作为节点模式提供。Claude Code 的 `/memory` 命令和 pro-workflow 的 `/learn-rule` 将情景缓冲区外部化为 markdown 文件。Letta 的睡眠时计算在空闲时间运行 Self-Reflector，因此主要智能体保持延迟绑定。OpenAI Agents SDK 不直接提供 Reflexion；你可以使用自定义 Guardrail（按分数拒绝轨迹）和跨运行持久化的内存 `Session` 来构建它。

## 发布它

`outputs/skill-reflexion-buffer.md` 创建并维护一个情景缓冲区，具有反思捕获、TTL 和去重功能。给定任务类和失败，它会发出一个对下一次试验真正有帮助的反思（而不是通用的“更加小心”）。

## 练习

1. 从二元评估器切换到返回距离度量（与目标的差距）的标量评估器。它收敛得更快吗？
2. 为反思添加 10 次试验的 TTL。在那之后，较旧的反思是有害还是有益？
3. 实现启发式评估器：如果相同动作重复，则将试验标记为卡住。这与 Self-Reflector 如何交互？
4. 使用忽略反思的对抗性 Actor 运行 Reflexion。强制 Actor 注意到它们的最小反思提示工程是什么？
5. 阅读 Reflexion 论文的第 4 节关于 AlfWorld 的内容。在概念上重现 130% 的成功率改进：与 vanilla ReAct 的关键差异是什么？

## 关键术语

| 术语 | 人们说的 | 实际含义 |
|------|----------|----------|
| Reflexion | “自我纠正” | Shinn 等人，2023 — Actor、Evaluator、Self-Reflector 加上情景记忆 |
| 语言强化 | “无梯度学习” | 自然语言反思预先添加到下一次试验的提示中 |
| 情景记忆 | “每任务反思” | 一个任务类的先前反思的有界缓冲区 |
| 标量评估器 | “二元成功信号” | 来自真实标签的通过/失败或数值分数 |
| 启发式评估器 | “基于模式的检测器” | 预定义的失败特征（例如卡住循环、步骤过多） |
| 自评估器 | “LLM 作为自身轨迹的评判者” | 当没有真实标签时的低信号后备——与基于工具的验证配合使用 |
| 记忆腐烂 | “过时的反思” | 情景缓冲区充满过时条目；通过压缩/TTL 修复 |
| 睡眠时反思 | “异步自我反思” | 在热路径之外运行 Self-Reflector，使主要智能体保持快速 |
