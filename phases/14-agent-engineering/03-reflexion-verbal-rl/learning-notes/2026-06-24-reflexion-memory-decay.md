# Reflexion 与记忆管理学习笔记

> 日期: 2026-06-24

## 1. Reflexion 核心模式

Reflexion 让智能体通过**自然语言反思**学习，无需梯度更新。三个组件：

| 组件 | 职责 |
|------|------|
| **Actor** | 执行任务（ReAct 风格循环） |
| **Evaluator** | 评估结果（二元/启发式/自评估） |
| **Self-Reflector** | 分析失败原因，生成自然语言反思 |

**情景记忆**：存储历史反思的有界列表，每次试验前注入提示。反思写入后，下次试验从头开始但能看到反思。

## 2. 三种评估器

- **标量**：通过/失败，信号最强（如测试通过、答案正确）
- **启发式**：预定义失败特征（如重复动作=卡住、步骤过多=低效）
- **自评估**：LLM 为自己打分，无真实标签时的后备方案

2026 年默认做法：标量优先 → 自评估兜底 → 启发式做安全护栏。

## 3. 记忆腐烂问题

**本质**：反思积累后，旧条目过时或错误，干扰决策且拖慢检索。

**解决方案**：

| 策略 | 做法 |
|------|------|
| **TTL** | 给反思设过期时间，自动删除 |
| **压缩合并** | 多条相关反思合成一条通用规则 |
| **访问频率淘汰** | 长期未调用的反思自动降级 |
| **验证过滤** | 写入前检查反思是否有用，过滤"迷信反思" |
| **分层存储** | 热记忆（小、快）+ 冷记忆（大、按需检索） |
| **睡眠时清理** | 后台智能体定期扫描整理 |

最实用组合：**TTL + 压缩 + 验证过滤**。

## 4. CLAUDE.md 膨胀问题

CLAUDE.md 写入过多经验教训会臃肿，缓解方式：

1. **定期压缩** — 合并重复/过时的教训
2. **TTL 机制** — 设过期时间自动清理
3. **分层存储** — 核心规则放 CLAUDE.md，详细反思放 `.claude/rules/`
4. **设行数上限** — 如不超过 200 行，超出必须压缩
5. **Git 追踪** — 定期 `git log` 审查历史，错误规则直接 revert
6. **给规则加元数据** — 记录来源、时间、可信度

核心原则：CLAUDE.md 是需要维护的配置文件，不是 append-only 日志。

## 5. Letta 平台

Letta（原名 MemGPT）是 AI 智能体记忆管理平台，解决"如何让 AI 跨会话记住经验"：

- **持久化记忆**：跨会话长期存储信息
- **睡眠时计算**：主智能体空闲时，后台智能体自动反思并写入内存块
- **分层记忆**：类似 OS 内存分页，有主内存、存档等层级

是 Reflexion 模式的生产级实现——异步 Self-Reflector 持续反思整理记忆。

## 6. 元数据的作用

给每条规则加注释，记录辅助信息：

```markdown
<!-- added: 2026-06-20 | confidence: high | source: 生产环境踩坑 -->
- 不要用 requests 库，用 httpx
```

| 字段 | 作用 |
|------|------|
| `added` | 判断是否过时 |
| `confidence` | 规则确定程度（high/medium/low） |
| `source` | 得出依据（踩坑/测试/文档） |
| `deprecated` | 是否已被替代 |

没有元数据，三个月后无法判断规则该保留还是清理。本质是**给知识打标签**，方便维护。

## 7. 生产系统中的 Reflexion 变体

| 系统 | 实现方式 |
|------|----------|
| Claude Code | CLAUDE.md 经验教训 |

共同洞察：**自然语言是足够丰富的媒介，能在运行之间传递"从失败中学到的东西"**。
