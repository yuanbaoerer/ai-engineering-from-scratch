# 多智能体辩论与协作

> Du 等人（ICML 2024，"Society of Minds"）运行 N 个模型实例，各自独立提出答案，然后在 R 轮中互相批评，最终收敛。提升事实准确性、规则遵循和推理能力。稀疏拓扑在 token 成本上优于全连接。

**类型：** 学习 + 构建
**语言：** Python（标准库）
**前置课程：** 阶段 14 · 12（工作流模式），阶段 14 · 05（Self-Refine 和 CRITIC）
**时间：** ~60 分钟

## 学习目标

- 解释辩论协议：N 个提议者，R 轮，收敛到共享答案。
- 描述辩论如何提升事实准确性、规则遵循和推理能力。
- 解释稀疏拓扑：并非每个辩论者都需要看到其他所有人。
- 使用标准库实现基于脚本 LLM 的全连接和稀疏变体辩论；衡量 token 成本与准确率。

## 问题背景

Self-Refine（第 05 课）是单个模型自我批评——存在群体思维风险。CRITIC（第 05 课）将批评建立在外部工具上——但并不总是可用。辩论引入了第三种模式：多个实例、交叉批评、通过分歧收敛。

## 核心概念

### 心智社会（Du 等人，ICML 2024）

- N 个模型实例独立地对同一问题提出答案。
- 在 R 轮中，每个模型阅读其他人的提议并加以批评。
- 模型根据批评更新自己的答案。
- R 轮后，返回收敛的答案。

原始实验由于成本原因使用了 N=3, R=2。在困难问题（MMLU、GSM8K、棋步有效性、传记生成）上，准确率随智能体数量和轮数增加而提升。

跨模型组合优于单模型辩论：ChatGPT + Bard 联合 > 各自单独。

### 稀疏拓扑

"Improving Multi-Agent Debate with Sparse Communication Topology"（arXiv:2406.11776，2024-2025）表明全连接辩论并非总是最优。稀疏拓扑（星型、环型、中心辐射型）可以在更低 token 成本下达到相同准确率。每个辩论者只看到部分同伴。

含义：

- 全连接 N=5, R=3 = 5 × 3 = 15 个提议，每个读取 4 个同伴 = 60 次批评操作。
- 星型 N=5, R=3（1 个中心 + 4 个辐射） = 15 个提议，辐射节点只读取中心 = 12 次批评操作。

### 辩论何时有帮助

- **事实准确性。** N 个独立提议，交叉验证减少幻觉。
- **规则遵循。** 棋步有效性——一个模型遗漏规则，其他模型捕捉到。
- **开放式推理。** 多种视角聚焦到正确答案。

### 辩论何时有害

- **延迟敏感的用户体验。** N × R 轮串行可能带来不可接受的延迟。
- **成本敏感的规模化。** 每个问题需要 N × R 个 token。
- **简单事实查询。** 一次查询比五次辩论更便宜。

### 2026 年实际应用场景

- **Anthropic 编排者-工作者**（第 12 课）——辩论的一个变体，带有综合步骤。
- **LangGraph 监督者**（第 13 课）——中央路由 + 专业智能体可以将辩论实现为一个节点。
- **OpenAI Agents SDK**（第 16 课）——智能体来回交接进行迭代批评。
- **多智能体评估** ——将辩论 + 评估者-优化器配对以获取评估信号。

### 此模式的常见陷阱

- **收敛崩溃。** 所有智能体收敛到第一个错误答案。通过强制分歧轮次缓解。
- **中心故障。** 在星型拓扑中，糟糕的中心会破坏所有人。轮换或使用多个中心。
- **提示同质化。** 所有智能体使用相同提示；产生相同答案。使用多样化提示和/或模型。

## 构建它

`code/main.py` 实现了标准库辩论：

- `Debater` 类（带每个辩论者观点漂移的脚本 LLM）。
- `FullMeshDebate` 和 `SparseDebate` 运行器。
- 三个问题：一个事实性、一个基于规则、一个推理。
- 指标：收敛答案、收敛轮数、总批评操作数。

运行：

```
python3 code/main.py
```

输出：每个协议的准确率和成本；稀疏拓扑在 2/3 个问题上以更低成本匹配全连接。

## 使用它

- **Anthropic 编排者-工作者** 用于简单的 2-3 个工作者辩论。
- **LangGraph** 用于带检查点的有状态多轮辩论。
- **自定义** 用于研究或专门的正确性保证。

## 交付它

`outputs/skill-debate.md` 提供多智能体辩论的脚手架，可配置拓扑、N、R 和收敛规则。

## 练习

1. 实现"强制分歧"规则：在第 1 轮，每个辩论者必须提出不同的提议。衡量对收敛速度的影响。
2. 添加置信度加权聚合：辩论者返回（答案，置信度）；聚合器按置信度加权。是否有帮助？
3. 将一个"智能体"替换为具有不同观点的不同脚本 LLM。异构性是否提升准确率？
4. 衡量全连接与稀疏在 3 个问题上的 token 成本。绘制成本与准确率图表。
5. 阅读 Society of Minds 论文。将你的玩具系统移植到 N=5, R=3。什么会出问题？什么会变好？

## 关键术语

| 术语 | 常见说法 | 实际含义 |
|------|---------|----------|
| 辩论 | "多智能体批评" | N 个提议者，R 轮交叉批评，收敛 |
| 全连接 | "每个人都读每个人" | 每个辩论者每轮读取所有同伴 |
| 稀疏拓扑 | "有限同伴视图" | 辩论者只读取部分同伴 |
| 中心辐射 | "星型拓扑" | 一个中心辩论者，N-1 个辐射节点只读取中心 |
| 收敛 | "达成一致" | 辩论者收敛到共享答案 |
| 心智社会 | "Du 等人的辩论论文" | ICML 2024 多智能体辩论方法 |
