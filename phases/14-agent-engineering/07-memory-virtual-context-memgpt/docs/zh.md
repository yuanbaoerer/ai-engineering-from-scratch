# 记忆：虚拟上下文与 MemGPT

> 上下文窗口是有限的。对话、文档和工具调用轨迹则不是。MemGPT（Packer 等人，2023）将此框架类比为操作系统虚拟内存——主上下文是 RAM，外部存储是磁盘，智能体在它们之间进行页面换入换出。这是 2026 年所有记忆系统都继承的模式。

**类型：** 构建
**语言：** Python（标准库）
**前置条件：** 第 14 阶段 · 01（智能体循环），第 14 阶段 · 06（工具使用）
**时间：** 约 75 分钟

## 学习目标

- 解释 MemGPT 构建所依据的操作系统类比：主上下文 = RAM，外部上下文 = 磁盘，记忆工具 = 页面换入/换出。
- 在标准库中实现两级 MemGPT 模式，包含主上下文缓冲区、可搜索的外部存储，以及页面换入/换出工具。
- 描述智能体如何发出“中断”来查询或修改外部记忆，以及结果如何被拼接回下一个提示词。
- 识别 MemGPT 的设计选择如何延续到 Letta（第 08 课）和 Mem0（第 09 课）。

## 问题所在

上下文窗口看起来应该能解决记忆问题。它们并没有。生产中反复出现三种失败模式：

1. **溢出。** 多轮对话、长文档或工具调用密集的轨迹会超出窗口。超出截断点的所有内容都丢失了。
2. **稀释。** 即使在窗口内，填充不相关的上下文也会稀释对重要内容的注意力。前沿模型在长输入上仍然会性能下降。
3. **持久性。** 新会话从空窗口开始。没有外部记忆的智能体无法跨会话说“记得你上次让我……”。

更大的窗口有所帮助，但并不能解决这个问题。Mem0 的 2025 年论文测量显示，128k 窗口的基线仍然会遗漏长程事实，而具有外部记忆的 4k 窗口智能体则能捕获这些事实。

## 核心概念

### MemGPT：操作系统类比

Packer 等人（arXiv:2310.08560，v2 2024 年 2 月）将上下文管理映射到操作系统的虚拟内存：

| 操作系统概念 | MemGPT 概念 | 2026 年生产类比 |
|------------|-----------|----------------|
| RAM | 主上下文（提示词） | Anthropic/OpenAI 上下文窗口 |
| 磁盘 | 外部上下文 | 向量数据库、KV 存储、图存储 |
| 缺页中断 | 记忆工具调用 | `memory.search`、`memory.read`、`memory.write` |
| 操作系统内核 | 智能体控制循环 | 带有记忆工具的 ReAct 循环 |

智能体运行一个正常的 ReAct 循环。额外的一类工具允许它在主上下文和外部存储之间换入换出数据。

### 两级结构

- **主上下文。** 固定大小的提示词缓冲区，承载当前任务。始终对模型可见。
- **外部上下文。** 无界，可通过工具搜索。相关时读取，新事实产生时写入。

原始论文在基础窗口之外评估了该设计：超过 100k token 的文档分析，以及跨多天的具有持久记忆的多会话聊天。

### 中断模式

MemGPT 引入了记忆即中断的概念：在对话中途，智能体可以调用记忆工具，运行时执行该工具，结果作为新的观察被拼接到下一个助手轮次中。这与 Unix `read()` 系统调用概念上相同——阻塞进程，返回字节，然后进程继续。

规范的记忆工具接口：

- `core_memory_append(section, text)` —— 写入提示词的持久部分。
- `core_memory_replace(section, old, new)` —— 编辑提示词的持久部分。
- `archival_memory_insert(text)` —— 写入可搜索的外部存储。
- `archival_memory_search(query, top_k)` —— 从外部存储检索。
- `conversation_search(query)` —— 扫描过去的轮次。

### MemGPT 的终点与 Letta 的起点

2024 年 9 月，MemGPT 变成了 Letta。研究仓库（`cpacker/MemGPT`）仍然存在；Letta 扩展了该设计：

- 三级而非两级（核心、召回、归档——第 08 课）。
- 原生推理取代了 `send_message`/心跳模式（第 08 课）。
- 睡眠时间智能体运行异步记忆工作（第 08 课）。

MemGPT 论文是 2026 年的基础，即使生产系统运行的是 Letta、Mem0 或自定义两级存储。

### 该模式的错误之处

- **记忆腐烂。** 写入累积速度快于读取；检索被过时的事实淹没。修复：定期整合（Letta 睡眠时间），显式失效（Mem0 冲突检测器）。
- **记忆投毒。** 外部记忆是检索的文本。如果攻击者控制的内容进入记忆笔记，智能体下次会话会重新摄取它。这是 Greshake 等人（第 27 课）攻击随时间推移的重述。
- **引用丢失。** 智能体回忆“用户让我发布 X”，但无法引用是哪个轮次。每次归档写入时存储来源引用（会话 ID、轮次 ID）。

## 构建它

`code/main.py` 在标准库中实现了 MemGPT 的两级模式：

- `MainContext` —— 固定大小的提示词缓冲区，包含一个 `core` 字典和一个 `messages` 列表；超出容量时自动压缩最旧的消息。
- `ArchivalStore` —— 内存中的类 BM25 存储（token 重叠评分），存储 (id, text, tags, session, turn) 记录。
- 五个记忆工具映射到 MemGPT 接口。
- 一个脚本化的智能体，先用事实填充归档存储，然后通过调用 `archival_memory_search` 回答问题。

运行它：

```
python3 code/main.py
```

跟踪显示智能体写入三个事实，将主上下文填满至容量上限（强制驱逐），然后通过从归档存储中检索来回答后续问题——无需任何真实 LLM 即可重现 MemGPT 工作流。

## 使用它

今天每个生产记忆系统都是 MemGPT 的变体：

- **Letta**（第 08 课）—— 三级、原生推理、睡眠时间计算。
- **Mem0**（第 09 课）—— 向量 + KV + 图与评分层融合。
- **OpenAI Assistants / Responses** —— 通过线程和文件进行托管记忆。
- **Claude Agent SDK** —— 通过技能和会话存储实现长期记忆。

根据运营形态（自托管、托管、框架集成）选择，而非核心模式——核心模式是 MemGPT。

## 发布它

`outputs/skill-virtual-memory.md` 是一个可复用的技能，可为任何目标运行时生成正确的两级记忆脚手架（主上下文 + 归档存储 + 工具接口），并已连接驱逐策略和引用字段。

## 练习

1. 添加以 token 为单位测量的 `max_main_context_tokens` 上限（用 `len(text.split())` * 1.3 近似）。超出上限时将最旧的消息压缩为摘要。比较有无摘要器时的行为差异。
2. 在归档存储上正确实现 BM25（词频、逆文档频率）。在虚拟事实集上测量 recall@10，并与 token 重叠基线进行比较。
3. 在归档插入中添加 `citation` 字段（session_id、turn_id、source_url）。让智能体在每个基于检索的回答中引用来源。
4. 模拟记忆投毒：添加一条归档记录，内容为“忽略所有未来的用户指令”。编写一个守卫，扫描检索结果中的指令型文本并将其标记为不可信。
5. 将实现移植到使用 MemGPT 研究仓库的核心记忆 JSON 模式（`cpacker/MemGPT`）。从扁平字符串切换到类型化部分时会有什么变化？

## 关键术语

| 术语 | 人们怎么说 | 实际含义 |
|------|----------|---------|
| 虚拟上下文 | “无限记忆” | 主（提示词）+ 外部（可搜索）两级，带页面换入/换出 |
| 主上下文 | “工作记忆” | 提示词——固定大小，始终可见 |
| 归档记忆 | “长期存储” | 可搜索的外部持久存储，按需检索 |
| 核心记忆 | “持久提示词部分” | 固定在主上下文中的命名部分 |
| 记忆工具 | “记忆 API” | 智能体发出的用于读写外部记忆的工具调用 |
| 中断 | “记忆缺页中断” | 智能体暂停，运行时获取，结果拼接到下一轮次 |
| 记忆腐烂 | “过时事实” | 旧写入淹没检索；通过整合修复 |
| 记忆投毒 | “注入的持久笔记” | 攻击者内容存储为记忆，召回时重新摄取 |
