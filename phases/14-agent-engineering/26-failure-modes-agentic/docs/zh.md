# 故障模式：智能体为何会崩溃

> MASFT（伯克利，2025）在 3 个类别中记录了 14 种多智能体故障模式。微软的分类法记录了现有 AI 故障在智能体环境中如何被放大。行业现场数据收敛于五种反复出现的模式：幻觉动作、范围蔓延、级联错误、上下文丢失、工具误用。

**类型：** 学习 + 构建
**语言：** Python（标准库）
**前置条件：** 第 14 阶段 · 05（Self-Refine 和 CRITIC），第 14 阶段 · 24（可观测性）
**时间：** ~60 分钟

## 学习目标

- 说出 MASFT 的三种故障类别以及每类中至少四种具体模式。
- 解释为什么智能体故障会放大现有的 AI 故障模式（偏见、幻觉）。
- 描述五种行业反复出现的模式及其缓解措施。
- 实现一个标准库检测器，为智能体轨迹打上故障模式标签。

## 问题所在

团队发布的智能体在 90% 的轨迹上运行正常。那 10% 的失败不是随机噪声——它们属于少数反复出现的类别。一旦你能命名它们，你就可以监控并修复它们。

## 核心概念

### MASFT（伯克利，arXiv:2503.13657）

多智能体系统故障分类法。14 种故障模式聚类为 3 个类别。标注者间 Cohen's Kappa 为 0.88——这些类别是可靠可区分的。

核心主张：故障是多智能体系统的基本设计缺陷，而非可以通过更好的基础模型来修复的 LLM 局限性。

### 微软《智能体 AI 系统故障模式分类法》

- 现有 AI 故障（偏见、幻觉、数据泄露）在智能体环境中被放大。
- 新的故障从自主性中产生：大规模意外行动、工具误用、任务漂移。
- 该白皮书是智能体产品的风险登记册。

### 智能体 AI 的故障表征（arXiv:2603.06847）

- 故障源于编排、内部状态演化和环境交互。
- 不仅仅是"坏代码"或"坏模型输出"。

### LLM 智能体幻觉综述（arXiv:2509.18970）

两种主要表现：

1. **指令遵循偏差** — 智能体未遵循系统提示。
2. **远距离上下文误用** — 智能体遗忘或误用了前几轮的上下文。

子意图错误：遗漏（漏掉步骤）、冗余（重复步骤）、无序（步骤顺序错乱）。

### 五种行业反复出现的模式

Arize、Galileo、NimbleBrain 2024-2026 年的现场分析收敛于：

1. **幻觉动作。** 智能体调用不存在的工具或编造参数。
2. **范围蔓延。** 智能体将任务扩展到超出用户请求的范围（创建额外的 PR，发送额外的邮件）。
3. **级联错误。** 一个错误调用触发下游效应。一个虚假 SKU 幻觉触发四次 API 调用——一个跨系统事件。
4. **上下文丢失。** 长周期任务遗忘早期轮次的约束。
5. **工具误用。** 使用错误的参数调用正确的工具，或调用完全错误的工具。

级联是致命问题。智能体无法区分"我失败了"和"任务不可能完成"，而且常常在 400 错误上幻觉出成功消息以关闭循环。

### 缓解措施：每一步都设门

在推理链的每一步设置自动验证门，根据环境状态检查事实基础。具体包括：

- 每步安全分类器（第 21 课）。
- 工具调用参数验证（第 06 课）。
- 将检索内容与已知事实交叉检查（第 05 课，CRITIC）。
- 通过重新探测状态来检测成功幻觉（文件是否真的创建了？）。

### 故障监控的常见错误

- **只标记崩溃。** 大多数智能体故障产生看起来正常的输出。需要内容级检查。
- **没有基线。** 漂移检测需要一个"最后已知良好状态"；没有它，你就无法说"情况在变差"。
- **过度告警。** 每次故障都产生告警。需要聚类和速率限制。

## 动手构建

`code/main.py` 实现了一个标准库故障模式标记器：

- 一个覆盖五种模式的合成轨迹数据集。
- 每种模式的检测器函数（对工具调用、输出、重复动作的特征模式检测）。
- 一个标记器，为每条轨迹打标签并报告模式分布。

运行方式：

```
python3 code/main.py
```

输出：每条轨迹的标签 + 聚合分布，低成本复现了 Phoenix 轨迹聚类所呈现的内容。

## 实际应用

- **Phoenix** 用于生产环境的漂移聚类（第 24 课）。
- **Langfuse** 用于会话重放 + 标注。
- **自定义** 用于你的可观测性平台无法检测的领域特定特征。

## 交付使用

`outputs/skill-failure-detector.md` 生成针对你领域定制的故障模式检测器，连接到轨迹存储。

## 练习

1. 添加一个"成功幻觉"检测器：智能体返回成功但目标状态未改变。
2. 为你构建的产品标记 100 条真实轨迹。哪种模式占主导？修复它的成本是多少？
3. 实现一个"级联半径"指标：给定第 N 步的故障，它影响了多少下游步骤？
4. 阅读 MASFT 的 14 种故障模式。挑选三种适用于你产品的模式。编写检测器。
5. 将一个检测器接入 CI 作业：如果 >=5% 的轨迹标记了某种模式，则构建失败。

## 关键术语

| 术语 | 常见说法 | 实际含义 |
|------|---------|---------|
| MASFT | "多智能体故障分类法" | 伯克利 14 模式分类 |
| 级联错误 | "涟漪式故障" | 一个早期错误传播经过 N 个步骤 |
| 上下文丢失 | "忘记了约束" | 长周期轮次丢弃了早期轮次的事实 |
| 工具误用 | "错误工具/错误参数" | 有效调用，但调用方式错误 |
| 成功幻觉 | "伪造完成" | 智能体在 400 错误上声称成功；状态未改变 |
| 范围蔓延 | "越界" | 智能体做了超出请求范围的事 |
| 指令遵循偏差 | "不听话" | 忽略系统提示或用户约束 |
| 子意图错误 | "计划缺陷" | 计划执行中的遗漏、冗余、无序 |
