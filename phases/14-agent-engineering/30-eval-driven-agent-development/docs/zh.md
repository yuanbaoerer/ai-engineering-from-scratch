# 评估驱动的智能体开发

> Anthropic 的指导："从简单的 prompt 开始，用全面的评估来优化它们，只在需要时才添加多步骤智能体系统。"评估不是最后一步。它是驱动 Phase 14 中所有其他选择的外循环。

**类型：** 学习 + 构建
**语言：** Python（标准库）
**前置要求：** Phase 14 全部课程。
**时间：** 约 60 分钟

## 学习目标

- 说出三个评估层级——静态基准测试、自定义离线评估、在线生产评估——以及各自的用途。
- 解释评估器-优化器紧循环。
- 描述 2026 年最佳实践：评估与代码放在一起、在 CI 中运行、门控 PR。
- 将 Phase 14 的每节课关联到它生成的评估用例。

## 问题

智能体在演示中通过。它们在生产中以演示无法预测的方式失败。基准测试回答的是"这个模型是否广泛具备能力？"而不是"这个智能体是否为我的产品发布了正确的补丁？"答案是：在三个层级上运行评估，持续运行，每个护栏和学到的规则都映射到一个评估用例。

## 概念

### 三个评估层级

1. **静态基准测试** — SWE-bench Verified 用于代码（第 19 课），WebArena/OSWorld 用于浏览/桌面（第 20 课），GAIA 用于通用能力（第 19 课），BFCL V4 用于工具使用（第 06 课）。用于跨模型比较和回归门控。数据污染是真实存在的：SWE-bench+ 发现 32.67% 的解决方案泄露。务必报告 Verified / +-audit 过的分数。

2. **自定义离线评估** — 你产品的形态：
   - LLM-as-judge（Langfuse、Phoenix、Opik — 第 24 课）。
   - 基于执行的（运行补丁，检查测试）。
   - 基于轨迹的（将动作序列与黄金标准对比；OSWorld-Human 显示顶级智能体使用了 1.4-2.7 倍于黄金标准的步数）。

3. **在线评估** — 生产环境：
   - 会话回放（Langfuse）。
   - 护栏触发的告警（第 16、21 课）。
   - 逐步成本/延迟追踪（第 23 课 OTel spans）。

### 评估器-优化器（Anthropic）

紧循环：

1. 提出者生成输出。
2. 评估器评判。
3. 精炼直到评估器通过。

这是自优化（第 05 课）的泛化。任何你关心的智能体流程都可以包裹在评估器-优化器中以提高可靠性。

### 2026 年最佳实践

- 评估与代码放在一起。
- 在每个 PR 的 CI 中运行。
- 在评估分数上门控合并（如"不得比 main 回归超过 5%"）。
- 每个护栏映射到一个评估用例。
- 每个学到的规则（Reflexion、pro-workflow learn-rule）映射到一个失败用例。

### 评估驱动开发失效的地方

- **没有基线。** 没有上一次已知良好状态的评估是不可读的。存储基线。
- **LLM-judge 没有依据。** Judge 也会产生幻觉。CRITIC 模式（第 05 课）— judge 在外部工具上找到依据。
- **过拟合评估。** 针对评估优化会偏离生产实用性。轮换用例。
- **不稳定的评估。** 非确定性的用例导致误报。固定种子，快照状态。

## 动手构建

`code/main.py` 是一个标准库的评估 harness：

- 带分类的用例注册表（benchmark、custom、online）。
- 脚本化待测智能体。
- 评估器-优化器循环：提出、评判、精炼直到通过或达到最大轮次。
- CI 门控：聚合通过率 + 对比基线的回归检测。

运行它：

```
python3 code/main.py
```

输出：每个用例的通过/失败、回归标志、CI 门控结论。

## 使用

- 将评估用例与智能体代码写在同一个仓库中。
- 在每个 PR 上通过 CI 运行。
- 回归时让构建失败。
- 追踪通过率随时间的变化。
- 每个生产失败都关联到一个新用例。

## 交付产出

`outputs/skill-eval-suite.md` 为一个智能体产品构建三层评估套件，带 CI 门控和回归追踪。

## 练习

1. 拿你的一次生产失败。写一个复现它的评估用例。你的智能体现在能通过吗？
2. 为你所在的领域构建一个 LLM-judge 评分标准，包含三个维度（事实性、语气、范围）。为 50 个会话评分。
3. 将评估套件接入 CI。回归超过 5% 时让构建失败。
4. 添加轨迹效率指标：智能体用了多少步 vs 黄金轨迹？
5. 将 Phase 14 的每节课映射到你套件中的一个评估用例。有遗漏吗？那就是需要填补的缺口。

## 关键术语

| 术语 | 常见说法 | 实际含义 |
|------|---------|---------|
| 静态基准测试 | "现成的评估" | SWE-bench、GAIA、AgentBench、WebArena、OSWorld |
| 自定义离线评估 | "领域评估" | LLM-as-judge / 基于执行 / 基于轨迹，针对你的产品形态 |
| 在线评估 | "生产评估" | 会话回放、护栏告警、成本/延迟追踪 |
| 评估器-优化器 | "提出-评判-精炼" | 迭代直到评估器通过 |
| CI 门控 | "合并拦截器" | 评估回归时让构建失败 |
| 基线 | "上一次已知的良好状态" | 用于检测回归的参考分数 |
| 轨迹效率 | "步数相对黄金标准" | 智能体步数除以人类专家最少步数 |
