# ReWOO 与 Plan-and-Execute 学习笔记

> 日期: 2026-06-23

## 1. ReWOO 的核心思想

ReWOO（Reasoning Without Observation）将 Agent 的规划与执行**解耦**：

- **ReAct**：思考 → 行动 → 观察 → 思考 → ...（交织循环）
- **ReWOO**：先制定完整计划，再并行执行，最后整合答案

**关键优势**：Token 消耗从 O(n²) 降为 O(n)，在 HotpotQA 上减少约 5 倍。

## 2. 三个角色的分工

| 角色 | 职责 | 输入 | 输出 |
|------|------|------|------|
| **Planner** | 生成计划 DAG | 用户问题 | 计划（步骤列表） |
| **Worker** | 执行工具调用 | 计划步骤 + 参数 | 证据（工具输出） |
| **Solver** | 整合最终答案 | 问题 + 计划 + 所有证据 | 人类可读的答案 |

**Worker 不能替代 Solver 的原因**：
- Worker 只做单一工具调用，不理解全局上下文
- Solver 有完整视角，能格式化输出、处理失败、综合判断

## 3. DAG 计划的结构

```python
Plan(steps=[
    PlanStep("E1", "search", {"query": "capital of France"}),
    PlanStep("E2", "search", {"query": "population of #E1"}),
    PlanStep("E3", "round_million", {"text": "#E2"}),
])
```

**每个 PlanStep 包含**：
- `id`：步骤标识（如 "E1"）
- `tool`：要调用的工具名
- `args`：参数字典，值可引用前序步骤（如 `#E1`）

**依赖关系通过 `#E1` 引用隐式表达**：
- E2 的参数包含 `#E1` → E2 依赖 E1
- E3 的参数包含 `#E2` → E3 依赖 E2

**在真实系统中**：Planner 是 LLM，通过提示词学习生成这种结构化格式（JSON/YAML/自定义语法）。

## 4. Token 效率对比

**ReAct 的 Token 消耗**：
```
Step 1: [问题] + 思考1 + 行动1 + 观察1
Step 2: [问题] + 思考1 + 行动1 + 观察1 + 思考2 + 行动2 + 观察2
...
```
每步携带完整历史，消耗随步骤数**二次方增长**。

**ReWOO 的 Token 消耗**：
```
Planner:  [问题] → 计划（一次性大调用）
Workers:  每个步骤独立执行（小调用，可并行）
Solver:   [问题] + 计划 + 所有证据 → 答案（一次性调用）
```
步骤间**解耦**，消耗**线性增长**。

## 5. 演进模式对比

| 模式 | 特点 | 适用场景 |
|------|------|---------|
| **ReWOO** | 静态计划，不可修改 | 工具已知的结构化任务 |
| **Plan-and-Execute** | 增加 Replanner，可部分执行后修订 | 需要灵活性的复杂任务 |
| **Plan-and-Act** | 合成计划数据训练，支持 30-50 步长周期 | Web/移动端操作 |

**Plan-and-Execute**（LangChain，2023）：ReWOO + 可选的 Replanner 节点，执行后可带回观察结果重新规划。

**Plan-and-Act**（ICML 2025）：扩展到长周期 Web Agent，关键贡献是合成计划训练数据。

## 6. Claude Plan 模式与 ReWOO 的区别

| 特性 | ReWOO | Claude Plan |
|------|-------|-------------|
| 规划器 | 独立模型 | 同一模型 |
| 执行器 | Worker（无推理能力） | 同一模型 |
| 求解器 | 独立 Solver | 无 |
| 动态调整 | 不可（静态计划） | 可（重新规划） |

**本质区别**：
- ReWOO = **架构级分工**（不同模型/角色）
- Claude Plan = **流程级分工**（同一模型的不同阶段）

Claude 的做法更灵活，但 Token 效率不如 ReWOO 的严格分离。

## 7. 准确率与架构的关系

**没有绝对优劣，取决于任务类型**：

- **ReWOO 优势场景**：结构化任务、工具调用序列明确、Token 敏感
- **Claude Plan 优势场景**：复杂推理、需要动态调整、开放性问题

ReWOO 的准确率提升来自**计划的完整性**（提前规划避免遗漏），Claude 的优势来自**模型的推理能力**（遇到问题能重新规划）。

## 8. 规划器蒸馏

论文的第二个贡献：用大模型（175B）的 Planner 输出训练小模型（7B）。

- 小模型负责规划，推理时不需要大模型
- 这是**模型训练方法**，但属于可选优化手段
- 目的是降低部署成本

## 9. 何时选择哪种模式

| 场景 | 推荐模式 |
|------|---------|
| 短任务、未知环境 | ReAct |
| 工具已知的结构化任务 | ReWOO |
| 需要动态调整的复杂任务 | Plan-and-Execute |
| 长周期 Web/移动端操作 | Plan-and-Act |

**Anthropic 的建议**：从最简单的开始。不要为一次工具调用构建 ReWOO，也不要为 40 步研究任务只用 ReAct。

## 10. 代码实现要点

代码实现了玩具版 ReWOO：

- **ToolRegistry**：工具注册表，管理工具调用和错误处理
- **topological()**：拓扑排序，确定 DAG 执行顺序
- **resolve_references()**：将 `#E1` 等占位符替换为实际证据
- **run_react_mock()**：模拟 ReAct 的 Token 消耗用于对比

**关键设计**：Worker 执行失败时返回错误字符串而非抛异常，Solver 可以优雅降级处理。
