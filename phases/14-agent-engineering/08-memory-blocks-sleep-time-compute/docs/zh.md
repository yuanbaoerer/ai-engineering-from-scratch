# 内存块与睡眠时计算（Letta）

> MemGPT 在 2024 年演变为 Letta。2026 年的演进增加了两个新概念：模型可以直接编辑的离散功能内存块，以及一个在主代理空闲时异步整合内存的睡眠时代理。这就是将内存扩展到超出单次对话范围的方式。

**类型：** 构建
**语言：** Python（标准库）
**前置课程：** 阶段 14 · 07（MemGPT）
**时间：** 约 75 分钟

## 学习目标

- 说出 Letta 使用的三个内存层级（核心、召回、归档）及其各自的作用。
- 解释内存块模式：Human 块、Persona 块以及作为一等类型化对象的用户自定义块。
- 描述睡眠时计算是什么，为什么它位于关键路径之外，以及为什么它可以比主代理使用更强大的模型。
- 实现一个脚本化的双代理循环，其中主代理提供响应，睡眠时代理在两轮之间整合块。

## 问题背景

MemGPT（第 07 课）解决了虚拟内存控制流问题。三个生产问题随之出现：

1. **延迟。** 每个内存操作都位于关键路径上。如果代理在用户等待时需要修剪、摘要或协调，尾部延迟会急剧上升。
2. **内存腐烂。** 写入不断积累。矛盾的事实仍然存在。检索淹没在过时的内容中。
3. **结构丢失。** 扁平的归档存储无法表达"Human 块始终在提示中；Persona 块始终在提示中；Task 块按会话切换。"

Letta（letta.com）是 2026 年的重写版本。内存块使结构变得显式；睡眠时计算将整合操作移出关键路径。

## 核心概念

### 三个层级

| 层级 | 范围 | 存储位置 | 写入者 |
|------|------|----------|--------|
| 核心（Core） | 始终可见 | 位于主提示内部 | 代理工具调用 + 睡眠时重写 |
| 召回（Recall） | 对话历史 | 可检索 | 自动轮次日志记录 |
| 归档（Archival） | 任意事实 | 向量 + KV + 图 | 代理工具调用 + 睡眠时摄入 |

核心层是 MemGPT 的核心。召回层是带有淘汰尾部的对话缓冲区。归档层是外部存储。这种划分清理了 MemGPT 两层级系统的职责重叠问题。

### 内存块

块（Block）是核心层的一个类型化、持久化、可编辑的段落。原始 MemGPT 论文定义了两种块：

- **Human 块** — 关于用户的事实（姓名、角色、偏好、目标）。
- **Persona 块** — 代理的自我概念（身份、语气、约束）。

Letta 将其泛化为任意用户自定义块：用于当前目标的 `Task` 块、用于代码库事实的 `Project` 块、用于硬约束的 `Safety` 块。每个块都有 `id`、`label`、`value`、`limit`（字符上限）、`description`（以便模型知道何时编辑它）。

块可通过工具接口进行编辑：

- `block_append(label, text)`
- `block_replace(label, old, new)`
- `block_read(label)`
- `block_summarize(label)` — 压缩接近上限的块。

### 睡眠时计算

这是 2025 年 Letta 新增的功能：在后台运行第二个代理，位于关键路径之外。睡眠时代理解理对话记录和代码库上下文，将 `learned_context` 写入共享块，并整合或失效归档记录。

由此产生的特性：

- **无延迟成本。** 主响应不等待内存操作。
- **允许使用更强大的模型。** 睡眠时代理可以使用更昂贵、更慢的模型，因为它不受延迟约束。
- **天然的整合窗口。** 在用户不等待时进行去重、摘要、失效矛盾的事实。

这种模式符合人类的工作方式：你完成任务，然后睡觉，长期记忆在夜间沉淀。

### Letta V1 与原生推理

Letta V1（`letta_v1_agent`，2026）废弃了 `send_message`/heartbeat 和内联 `Thought:` 标记，转而采用原生推理。Responses API（OpenAI）和带有扩展思考的 Messages API（Anthropic）在单独的通道上输出推理，通过轮次传递（在生产环境中跨提供者加密）。控制循环仍然是 ReAct。思考追踪是结构性的，而非提示形状的。

### 这种模式可能出错的地方

- **块膨胀。** 无限的 `block_append` 会快速达到限制。在写入之前接入一个块摘要器，以防止超过上限。
- **静默漂移。** 睡眠时代理重写了一个块，而主代理从未注意到。对块进行版本控制并在追踪中显示差异。
- **污染整合。** 睡眠时代理将攻击者可访问的内容处理到核心层。第 27 课的内容同样适用于睡眠时表面。

## 构建实现

`code/main.py` 实现了：

- `Block` — id、label、value、limit、description。
- `BlockStore` — CRUD + `near_limit(label)` 辅助函数。
- 两个脚本化代理 — `PrimaryAgent` 服务于一轮，`SleepTimeAgent` 在轮次之间进行整合。
- 一个追踪，展示了一个三轮对话，包含块写入，以及一个睡眠时过程，该过程对一个块进行摘要并失效了一个过时的事实。

运行方式：

```
python3 code/main.py
```

记录显示了分工：主轮次快速且产生原始写入；睡眠时过程进行压缩和清理。

## 使用方式

- **Letta**（letta.com）是参考实现。可自托管或使用托管云。
- **Claude Agent SDK 技能** 作为块状知识 — 技能是一个命名的、版本化的、可检索的指令块，代理按需加载。
- **自定义构建** 适用于希望控制存储后端的团队。使用 Letta API 契约以便日后可以迁移。

## 交付成果

`outputs/skill-memory-blocks.md` 为任何运行时生成一个带有睡眠时钩子的 Letta 风格块系统，包括安全规则和引用链接。

## 练习

1. 添加一个 `block_summarize` 工具，当 `near_limit` 返回 true 时，用模型生成的摘要替换块的值。哪个触发阈值可以同时最小化摘要调用和块溢出？
2. 在归档层实现睡眠时去重：两条文本重叠度 >90% 的记录合并为一条。仅在睡眠时过程中执行，永远不在关键路径上。
3. 对块进行版本控制。每次写入时记录旧值和差异。暴露 `block_history(label)`，以便运维人员调试"为什么代理忘记了 X"。
4. 将睡眠时代理视为不受信任的写入者。当它们修改 Persona 或 Safety 块时，需要第二代理审查才能提交。
5. 将示例移植为使用 Letta API（`letta_v1_agent`）。块的 schema 有何变化，原生推理如何改变追踪形状？

## 关键术语

| 术语 | 人们的说法 | 实际含义 |
|------|------------|----------|
| 内存块（Memory block） | "可编辑的提示段落" | 核心内存的类型化、持久化、LLM 可编辑段 |
| Human 块 | "用户记忆" | 关于用户的事实，固定在核心层 |
| Persona 块 | "代理身份" | 自我概念、语气、约束，固定在核心层 |
| 睡眠时计算（Sleep-time compute） | "异步内存工作" | 第二代理在关键路径之外进行的整合工作 |
| 核心 / 召回 / 归档 | "层级" | 三层内存划分：始终可见 / 对话 / 外部 |
| 块限制（Block limit） | "上限" | 每个块的字符限制；强制摘要 |
| 原生推理（Native reasoning） | "思考通道" | 提供者级别的推理输出，而非提示级别的 `Thought:` |
| 学习到的上下文（Learned context） | "睡眠输出" | 睡眠时代理写入共享块的事实 |
