# 编排模式：监督者、集群、层级

> 四种编排模式在 2026 年的框架中反复出现：监督者-工作者、集群/点对点、层级、辩论。Anthropic 的指导原则："关键是为你的需求构建正确的系统。"从简单开始；只有当单个智能体加五种工作流模式不够用时，才增加拓扑结构。

**类型：** 学习 + 构建
**语言：** Python（标准库）
**前置条件：** 阶段 14 · 12（工作流模式）、阶段 14 · 25（多智能体辩论）
**时间：** 约 60 分钟

## 学习目标

- 列出四种反复出现的编排模式及其适用场景。
- 描述 2026 年 LangChain 的建议：基于工具调用的监督 vs 监督者库。
- 解释 Anthropic 的"构建正确系统"规则及其对拓扑选择的指导。
- 用标准库针对脚本化的 LLM 实现全部四种模式。

## 问题

团队在需要之前就急于使用"多智能体"。四种模式在框架中反复出现；一旦你能说出它们的名字，就能选择合适的模式——或者完全跳过拓扑结构。

## 概念

### 监督者-工作者

- 一个中心化的路由 LLM 调度给专家智能体。
- 决策：循环回到自己、交给专家、终止。
- 专家之间互不交流；所有路由都经过监督者。

框架：LangGraph `create_supervisor`、Anthropic orchestrator-workers、CrewAI Hierarchical Process。

**2026 年 LangChain 的建议：** 通过直接工具调用进行监督，而非使用 `create_supervisor`。这样可以实现更精细的上下文工程控制——你可以精确决定每个专家看到什么。

### 集群/点对点

- 智能体通过共享工具表面直接交接。
- 没有中心路由器。
- 比监督者延迟更低（跳数更少）。
- 更难推理（没有单一控制点）。

框架：LangGraph swarm topology、OpenAI Agents SDK handoffs（当所有智能体都能交给所有其他智能体时）。

### 层级

- 监督者管理子监督者，子监督者管理工作者。
- 在 LangGraph 中实现为嵌套子图；在 CrewAI 中实现为嵌套团队。
- 以运维复杂性为代价，可扩展到大量智能体。

何时需要：当单个监督者的上下文预算无法容纳所有专家的描述时。

### 辩论

- 并行提议者 + 迭代式交叉批评（第 25 课）。
- 严格来说不算编排——更像验证——但在框架中作为拓扑选项出现。

### CrewAI Crew vs Flow

CrewAI 规范化了两种部署模式：

- **Flow** 用于确定性事件驱动自动化（生产环境的推荐起点）。
- **Crew** 用于自主的角色协作。

这与上述四种模式正交，但映射到拓扑：Flow 通常是监督者或层级；Crew 通常是带 LLM 路由器的监督者。

### Anthropic 的指导

"在 LLM 领域的成功不在于构建最复杂的系统，而在于为你的需求构建正确的系统。"

决策顺序：

1. 单智能体 + 工作流模式（第 12 课）——从这里开始。
2. 监督者-工作者——当你有 2-4 个专家时。
3. 集群——当延迟比推理清晰度更重要时。
4. 层级——仅当监督者上下文预算不足时。
5. 辩论——当准确率比成本更重要时。

### 此模式的常见错误

- **拓扑优先思维。** 在确定多智能体解决什么问题之前就说"我们需要多智能体"。
- **集群中的弹跳交接。** A -> B -> A -> B。使用跳数计数器。
- **虚假层级。** 因为"企业级"而设三层，实际只有两个团队。应该合并。

## 构建

`code/main.py` 用标准库针对脚本化的 LLM 实现了全部四种模式：

- `Supervisor` — 中心路由器。
- `Swarm` — 点对点直接交接。
- `Hierarchical` — 监督者的监督者。
- `Debate` — 并行提议者 + 批评。

每种模式处理相同的三意图任务（退款 / 缺陷 / 销售）。追踪路径各不相同。

运行：

```
python3 code/main.py
```

输出：每种模式的追踪 + 操作次数。监督者最简洁；集群最短；层级最深；辩论最昂贵。

## 使用

- **LangGraph** 用于监督者和层级（嵌套子图）。
- **OpenAI Agents SDK** 用于将交接作为工具（监督者形态）。
- **CrewAI Flow** 用于生产环境的确定性。
- **自定义** 用于辩论或需要精确控制时。

1. 将监督者-工作者转换为集群：移除路由器。什么会坏？什么会改善？

## 关键术语

| 术语 | 通俗说法 | 实际含义 |
|------|---------|---------|
| 监督者-工作者 | "路由器 + 专家" | 中心 LLM 调度给专家；专家之间互不交流 |
| 集群 | "点对点" | 通过共享工具直接交接；无中心路由器 |
| 层级 | "监督者的监督者" | 针对大量智能体的嵌套子图 |
| 辩论 | "提议者 + 批评" | 并行提议者，交叉批评（第 25 课） |
| 基于工具调用的监督 | "不用库的监督者" | 将监督者实现为直接工具调用以控制上下文 |
| Crew | "自主团队" | CrewAI 的基于角色的协作模式 |
| Flow | "确定性工作流" | CrewAI 的事件驱动生产模式 |
