# LangGraph：有状态图与持久化执行

> LangGraph 是 2026 年低级有状态编排的参考实现。智能体即状态机；节点即函数；边即转换；状态不可变，每步执行后自动检查点。从任意失败点精确恢复。

**类型：** 学习 + 构建
**语言：** Python（标准库）
**前置条件：** 第 14 阶段 · 01（智能体循环），第 14 阶段 · 12（工作流模式）
**时间：** 约 75 分钟

## 学习目标

- 描述 LangGraph 的核心模型：具有不可变状态、函数节点、条件边和步骤后检查点的状态机。
- 列出文档强调的四项能力：持久化执行、流式输出、人机协同、全面记忆。
- 解释 LangGraph 支持的三种编排拓扑：监督者模式、点对等（集群）模式、层级（嵌套子图）模式。
- 用标准库实现一个有状态图，包含不可变状态、条件边和检查点/恢复循环。

## 问题背景

智能体和工作流面临同一个问题：当一个 40 步的运行在第 38 步失败时，你希望从第 38 步恢复，而不是从头开始。二等公民的状态模型让运维人员不得不围绕一个假设全新运行的库来编写重试逻辑。

LangGraph 的设计解答：状态是一等公民的类型化对象，变更是显式的，检查点在每个节点后持久化。恢复只需一次 `load_state(session_id)` 调用。

## 核心概念

### 图

图由以下元素定义：

- **状态类型。** 一个类型化字典（或 Pydantic 模型），所有节点都读取和修改它。
- **节点。** 纯函数 `(state) -> state_update`。返回后更新合并到状态中。
- **边。** 节点之间的条件或直接转换。
- **入口和出口。** `START` 和 `END` 哨兵节点标记边界。

示例：一个包含 `classify`、`refund`、`bug`、`sales`、`done` 节点的智能体——一个路由工作流以图的形式表达。

### 持久化执行

每个节点返回后，运行时将状态序列化并写入检查点存储（SQLite、Postgres、Redis、自定义）。在第 N 步失败时，运行时可以通过 `resume(session_id)` 从第 N+1 步精确恢复。

LangGraph 文档明确强调了生产用户场景：Klarna、Uber、J.P. Morgan。其价值不在于图的形状，而在于图的形状加上检查点使得恢复成本极低。

### 流式输出

每个节点都可以产出部分输出。图按节点粒度将增量事件流式传输给调用者，使 UI 在图运行过程中实时更新。

### 人机协同

在节点之间检查和修改状态。实现方式：在关键节点前暂停，将状态呈现给人工，接受修改后恢复。检查点使这一过程变得简单，因为状态已经是序列化的。

### 记忆

短期记忆（运行内——状态中的对话历史）和长期记忆（跨运行——通过检查点存储加独立的长期存储持久化）。LangGraph 通过工具集成外部记忆系统（Mem0、自定义）。

### 三种拓扑

1. **监督者模式。** 中央路由 LLM 将任务分派给专家子智能体。`langgraph-supervisor` 中的 `create_supervisor()`（不过 LangChain 团队在 2026 年建议通过工具调用直接实现，以获得更好的上下文控制）。
2. **集群/点对等模式。** 智能体通过共享工具界面直接交接，无需中央路由器。
3. **层级模式。** 监督者管理子监督者，以嵌套子图实现。

### 常见误区

- **检查点粒度太小。** 仅检查点对话轮次会导致工具状态和记忆写入不可恢复。完整状态必须全部序列化。
- **节点不确定性。** 恢复假设节点输入产生相同的状态更新。随机种子、墙钟时间、外部 API 调用都必须被捕获。
- **过度使用条件边。** 每条边都是条件的图是一个无法推理的状态机。建议使用线性链加少量分支。

## 构建

`code/main.py` 实现了一个标准库有状态图：

- `State` — 包含 `messages`、`step`、`route`、`output`、`human_approval` 的类型化字典。
- `Node` — 可调用对象，接收状态并返回更新字典。
- `StateGraph` — 节点 + 边 + 条件边 + 运行 + 恢复。
- `SQLiteCheckpointer`（内存伪实现）— 每个节点后序列化状态；`load(session_id)` 恢复。
- 演示图：classify -> 分支（refund / bug / sales）-> 人工审批门 -> 发送。

运行方式：

```
python3 code/main.py
```

跟踪输出显示首次运行在人工审批门失败，状态持久化，然后恢复产生最终输出。

## 关键术语

| 术语 | 常见说法 | 实际含义 |
|------|---------|---------|
| 状态图 | "智能体即状态机" | 类型化状态 + 节点 + 边 + 归约器 |
| 检查点存储 | "持久化后端" | 每个节点后序列化状态；支持恢复 |
| 归约器 | "状态合并器" | 将当前状态与节点更新组合的函数 |
| 条件边 | "分支" | 由状态函数选择的边 |
| 子图 | "嵌套图" | 作为节点嵌入另一个图的图 |
| 持久化执行 | "从失败中恢复" | 以精确状态从最后一个成功节点重启 |
| 监督者 | "路由 LLM" | 专家子智能体的中央调度器 |
| 集群 | "P2P 智能体" | 智能体通过共享工具交接；无中央路由器 |
