# 技能库与终身学习（Voyager）

> Voyager（Wang et al., TMLR 2024）将可执行代码视为技能。技能是可命名、可检索、可组合的，并通过环境反馈进行精炼。这是 Claude Agent SDK 技能、skillkit 以及 2026 年技能库模式的参考架构。

**类型：** 构建
**语言：** Python（标准库）
**前置条件：** 阶段 14 · 07（MemGPT），阶段 14 · 08（Letta Blocks）
**时间：** ~75 分钟

## 学习目标

- 命名 Voyager 的三个组件——自动课程、技能库、迭代提示——以及各自的作用。
- 解释为什么 Voyager 将动作空间设为代码而非原始命令。
- 用标准库实现一个技能库，支持注册、检索、组合和基于失败的精炼。
- 将 Voyager 的模式映射到 2026 年 Claude Agent SDK 技能和 skillkit 生态系统。

## 问题背景

在每个会话中都从头重建所有能力的智能体会犯三个错误：

1. **浪费 token。** 每个任务都重新引导相同的推理过程。
2. **丢失进度。** 在会话 A 中学到的修正无法迁移到会话 B。
3. **长周期组合失败。** 复杂任务需要能力层级结构；单次提示无法表达它们。

Voyager 的解决方案：将每个可复用能力视为一段命名代码块，存储在库中，可通过相似性检索，与其他技能组合，并通过执行反馈进行精炼。

## 核心概念

### 三个组件

Voyager（arXiv:2305.16291）围绕三个组件构建智能体：

1. **自动课程。** 一个基于好奇心驱动的提议者根据智能体当前的技能集和环境状态选择下一个任务。探索是自下而上的。
2. **技能库。** 每个技能都是可执行代码。任务成功后添加新技能。技能通过查询与描述的相似性进行检索。
3. **迭代提示机制。** 失败时，智能体接收执行错误、环境反馈和自验证输出，然后精炼技能。

Minecraft 评估结果（Wang et al., 2024）：独特物品数量是基线的 3.3 倍，石制工具速度提升 8.5 倍，铁制工具速度提升 6.4 倍，地图遍历距离提升 2.3 倍。这些数字是 Minecraft 特定的，但模式可迁移。

### 动作空间 = 代码

大多数智能体发出原始命令。Voyager 发出 JavaScript 函数。一个技能是：

```
async function craftIronPickaxe(bot) {
  await mineIron(bot, 3);
  await mineStick(bot, 2);
  await placeCraftingTable(bot);
  await craft(bot, 'iron_pickaxe');
}
```

由子技能组合而成。按描述和嵌入向量键控存储。作为程序而非提示进行检索。

这就是 2026 年 Claude Agent SDK 技能：一个命名的、可检索的代码块加上智能体按需加载的指令。

### 技能检索

新任务"制作钻石镐"。智能体：

1. 嵌入任务描述。
2. 查询技能库中 top-k 相似技能。
3. 检索到 `craftIronPickaxe`、`mineDiamond`、`placeCraftingTable` 等。
4. 从检索到的原语 + 新逻辑组合出新技能。

这就是 MCP 资源（阶段 13）和 Agent SDK 技能实现的模式：在知识/代码表面上检索，限定在当前任务范围内。

### 迭代精炼

Voyager 的反馈循环：

1. 智能体编写一个技能。
2. 技能在环境中运行。
3. 返回三种信号之一：`success`、`error`（附带堆栈跟踪）、`self-verification failure`（自验证失败）。
4. 智能体使用该信号作为上下文重写技能。
5. 循环直到成功或达到最大轮次。

这是 Self-Refine（课程 05）应用于带有环境验证的代码生成。CRITIC（课程 05）使用外部工具作为验证者，是同一模式。

### 课程与探索

Voyager 的课程模块根据智能体已有和尚未完成的内容提出任务，如"在湖边建一个庇护所"。提议者使用环境状态 + 技能清单选择略高于当前能力的任务——探索的甜蜜点。

对于生产环境的智能体，这转化为"缺少什么"操作符：给定当前技能库和领域，我们还缺哪些技能？团队通常以课程评审的形式手动实现这一点。

### 该模式容易出错的地方

- **技能库腐化。** 同一个技能因略有不同的描述被添加 10 次。在写入时添加去重；检索时只返回一个。
- **组合技能漂移。** 父技能依赖的子技能被精炼了。对技能进行版本控制；固定在 v1 的父技能不会自动升级到 v3。
- **检索质量。** 当技能库增长到数百个时，基于技能描述的向量检索会退化。通过标签过滤和硬约束（"仅返回 `category=tooling` 的技能"）进行补充。

## 构建

`code/main.py` 实现了一个标准库技能库：

- `Skill` —— 名称、描述、代码（字符串形式）、版本、标签、依赖。
- `SkillLibrary` —— 注册、搜索（token 重叠）、组合（依赖拓扑排序）和精炼（更新时版本递增）。
- 一个脚本化的智能体，注册三个原语技能，组合第四个，遇到失败，然后精炼。

运行：

```
python3 code/main.py
```

跟踪输出显示了库的写入、检索、组合、一次失败的执行和 v2 精炼——完整的 Voyager 循环。

## 应用

- **Claude Agent SDK 技能**（Anthropic）—— 2026 年参考实现：每个技能都有描述、代码和指令；在智能体会话期间按需加载。
- **skillkit**（npm: skillkit）—— 面向 32+ AI 编码智能体的跨智能体技能管理。
- **自定义技能库** —— 领域特定（数据智能体的 SQL 技能、基础设施智能体的 Terraform 技能）。Voyager 模式可向下扩展。
- **OpenAI Agents SDK `tools`** —— 在低端；每个工具都是轻量级技能。

## 交付

`outputs/skill-skill-library.md` 为任意目标运行时生成一个 Voyager 形状的技能库，包含注册、检索、版本控制和精炼功能。

## 练习

1. 向 `compose()` 添加依赖环检测器。当技能 A 依赖 B 而 B 又依赖 A 时会发生什么？报错还是警告？
2. 实现按技能版本固定。当父技能组合子技能 `crafting@1` 时，`crafting@2` 的精炼不应静默升级父技能。
3. 用 sentence-transformers 嵌入（或 BM25 标准库实现）替换 token 重叠检索。在 50 个技能的玩具库上测量 retrieval@5。
4. 添加"课程"智能体：给定当前库和领域描述，提出 5 个缺失技能。每周调用一次。
5. 阅读 Anthropic 的 Claude Agent SDK 技能文档。将玩具库移植到 SDK 的技能 schema。可发现性有什么变化？

## 关键术语

| 术语 | 人们怎么说 | 实际含义 |
|------|-----------|----------|
| 技能 | "可复用能力" | 命名的代码块 + 描述，可通过相似性检索 |
| 技能库 | "智能体操作记忆" | 技能的持久存储，可搜索、可组合 |
| 课程 | "任务提议者" | 由当前能力缺口驱动的自下而上目标生成器 |
| 组合 | "技能 DAG" | 技能调用技能；执行时拓扑排序 |
| 迭代精炼 | "自纠正循环" | 环境反馈 + 错误 + 自验证折叠进下一个版本 |
| 动作空间即代码 | "程序化动作" | 发出函数而非原始命令，用于时间跨度较长的行为 |
| 写入去重 | "技能折叠" | 近重复描述折叠为一个规范技能 |
