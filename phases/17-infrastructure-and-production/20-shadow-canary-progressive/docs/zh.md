# LLM 的影子流量、金丝雀发布和渐进式部署

> LLM 发布结合了软件部署中最难的部分：没有单元测试、分散的故障模式、延迟的信号。流程是（1）影子模式（shadow mode）——将生产请求复制到候选模型，记录日志，零用户影响进行比较；能捕获明显的分布问题但不是质量保证；（2）金丝雀发布（canary rollout）——渐进式流量转移 10% → 25% → 50% → 75% → 100%，每步有门控；跟踪延迟百分位、成本/请求、错误/拒绝率、输出长度分布、用户反馈率；（3）确认稳定性后，针对不同备选方案进行 A/B 测试。不确定性是不可消除的——由于 GPU 浮点非结合律加上批大小差异，相同输入的运行间精度变化可达 15%。成本是变量而非常数——好 20% 的模型每次调用可能贵 3 倍。回滚速度是决定性的：如果回滚需要重新部署，你就太慢了。策略在配置/标志中；模型在注册表中带固定摘要；回滚 = 翻转策略 + 恢复阈值 + 在秒级固定旧模型。

**类型：** 学习
**语言：** Python（stdlib，玩具金丝雀渐进模拟器）
**前置课程：** 第 17 阶段 · 13（可观测性），第 17 阶段 · 21（A/B 测试）
**时间：** 约 60 分钟

## 学习目标

- 区分影子模式（零影响比较）、金丝雀（实时流量渐进式）和 A/B（稳定性确认的比较）。
- 枚举五个 LLM 特定的金丝雀指标（延迟、成本/请求、错误/拒绝、输出长度分布、用户反馈）。
- 解释为什么 LLM 不确定性（高达 15%）改变了发布中"稳定"的含义。
- 设计秒级完成的回滚路径（策略翻转）而非小时级（重新部署）。

## 问题

你发布了新模型。离线评估显示 3% 精度提升。你在生产中开启。24 小时内，成本上升 40%，用户点踩上升 8%，三个客户工单报告"奇怪的回答"。你回滚。重新部署花了 3 小时。你的周末毁了。

每一步都是可避免的。影子模式会在任何用户看到之前捕获 40% 的成本飙升。金丝雀会在点踩变化时停在 10%。策略标志回滚只需 30 秒。纪律正是填补"离线评估看起来不错"和"真实用户满意"之间差距的东西。

## 概念

### 影子模式

候选模型接收与生产相同的请求；输出被记录但不返回给用户。零用户影响。记录：

- 输出内容（与生产的差异）。
- token 计数（成本差）。
- 延迟。
- 拒绝和错误。

能捕获：成本暴增、长度回退、明显的拒绝变化、严重错误。不能捕获：用户会感知到的质量差异。影子是冒烟测试，不是质量测试。

### 金丝雀发布

带门控的渐进式流量转移。典型流程：1% → 10% → 25% → 50% → 75% → 100%。每步基于 5 个指标设置门控：

1. **延迟百分位**——P50、P95、P99。触发：金丝雀 P99 > 基线 1.5 倍。
2. **每请求成本**——混合美元。触发：比基线高 >20%。
3. **错误/拒绝率**——5xx 加显式拒绝。触发：基线 2 倍。
4. **输出长度分布**——均值 + P99。触发：分布偏移。
5. **用户反馈率**——点踩/工单提交。触发：基线 1.5 倍。

### 不确定性是新的方差

相同输入产生不同输出。原因：

- GPU 浮点非结合律（浮点归约顺序因批次不同而变化）。
- 批大小差异（相同提示在 128 批次 vs 16 批次中）。
- 采样（temperature > 0）。

实测：相同评估集上运行间精度变化高达 15%。发布中的"稳定"意味着指标在预期方差内，而非与基线相同。将门控设在噪声底之上。

### 成本是变量

好 20% 的模型每次调用可能贵 3 倍。成本/请求是五个门控之一。发布一个打破单位经济模型的"更好"模型是回滚案例。

### 回滚是武器

- 策略标志（功能标志系统）：在配置中翻转百分比；秒级完成。
- 模型固定（注册表摘要）：固定模型不会自动升级。
- 回滚 = 恢复标志 + 将固定摘要设为之前的版本。秒级，不是小时级。

如果你的栈需要重新部署才能回滚，在发布前修复它。

### 工具

**Argo Rollouts** / **Flagger**——Kubernetes 渐进式交付控制器。与 Istio/Linkerd 加权路由集成。

**Istio 加权路由**——服务网格级别的流量分割。

**KServe / Seldon Core**——带内置金丝雀的模型推理。

**功能标志**——LaunchDarkly、Flagsmith、Unleash。策略级翻转，无需重新部署。

### 指标节奏

金丝雀门控每 5-15 分钟检查一次，取决于流量量。1% 流量配合 10 req/min 给出每窗口 50-150 个数据点——延迟够用但用户反馈噪声大。10% 给出约 10 倍数据。渐进应在每步暂停足够长以积累足够样本。

### A/B 步骤是可选的

如果新模型明显不同（不同行为、不同成本曲线、不同语气），在金丝雀通过后以 50% 进行 A/B 测试。如果只是改进版本，金丝雀门控通过后直接到 100%。

### 你应该记住的数字

- 金丝雀流程：1% → 10% → 25% → 50% → 75% → 100%。
- 不确定性上限：相同输入上运行间方差高达 15%。
- 五个金丝雀指标：延迟、成本、错误/拒绝、输出长度、用户反馈。
- 成本门控：比基线高 >20% 触发。
- 回滚：秒级，不是小时级。

## 关键术语

| 术语 | 人们的说法 | 实际含义 |
|------|-----------|----------|
| 影子模式 | "复制到新模型" | 零影响地发送到候选模型进行记录 |
| 金丝雀 | "渐进式流量" | 带门控的渐进式用户暴露发布 |
| 门控 | "发布检查" | 阻止进展的指标阈值 |
| 不确定性 | "LLM 方差" | 不可消除的运行间差异 |
| 策略标志 | "标志翻转回滚" | 配置级回滚，秒级而非小时级 |
| 模型固定 | "注册表摘要" | 模型版本的不可变引用 |
| Argo Rollouts | "K8s 渐进式" | Kubernetes 原生金丝雀/回滚控制器 |
| KServe | "推理 K8s" | 带金丝雀原语的模型推理 |
| Istio 加权 | "网格分割" | 服务网格流量分割器 |
