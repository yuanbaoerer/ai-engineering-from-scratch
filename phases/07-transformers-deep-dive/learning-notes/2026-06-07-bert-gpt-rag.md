# 2026-06-07 学习记录：BERT、GPT、Transformer 架构与 RAG

> 本次学习围绕 Transformer 架构家族的分化、BERT 与 GPT 的本质区别、以及 RAG 检索增强生成的完整流程展开。

---

## 1. BERT 是什么

**BERT**（Bidirectional Encoder Representations from Transformers）是 Google 在 2018 年提出的预训练模型。

- **架构**：仅 Transformer 编码器，双向注意力（每个 token 可以看到所有其他 token）
- **预训练任务**：掩码语言建模（MLM）—— 随机遮住 15% token，预测原文
  - 80% 替换为 `[MASK]`，10% 替换为随机 token，10% 保持不变
  - 10% 随机 + 10% 不变是为了避免训练与推理的分布偏移
- **擅长任务**：分类、检索嵌入、NER、重排序（理解型任务）
- **现代演进**：ModernBERT（2024）用 RoPE + Flash Attention + 8K 上下文重建

## 2. BART 是什么

**BART**（Bidirectional and Auto-Regressive Transformer）是 Meta 在 2019 年提出的序列到序列模型。

- **架构**：编码器（双向）+ 解码器（自回归），是完整的 Transformer 架构
- **预训练任务**：文本损坏 → 恢复（支持 5 种损坏策略：token 删除、掩码、填充、重排、旋转）
- **擅长任务**：摘要、翻译、问答（需要理解完整输入再生成的任务）

## 3. Transformer vs GPT — 架构蓝图 vs 具体模型

```
Transformer (2017)          ≈ "汽车"这个概念
GPT (2018)                  ≈ "特斯拉 Model S"（只取解码器）
BERT (2018)                 ≈ "丰田卡罗拉"（只取编码器）
T5 / BART (2019/2020)       ≈ 完整的汽车（编码器 + 解码器）
```

原始 Transformer 包含编码器 + 解码器，GPT 只截取了**解码器**部分，同时去掉了交叉注意力（因为没有编码器可交叉）。

## 4. BERT 与 GPT 的关系 — 互补而非竞争

BERT 和 GPT 是**完全独立的模型家族**，从未融合：

```
原始 Transformer (2017)
      ├── BERT 路线（编码器）：BERT → RoBERTa → DeBERTa → ModernBERT
      └── GPT 路线（解码器）：GPT-1 → GPT-2 → GPT-3 → GPT-4 → GPT-5
```

BERT 对 GPT 的贡献是**思想层面**的（证明了预训练的价值），不是架构层面的。

在现代 AI 系统中，它们**协作而非替代**：
- BERT 负责检索、嵌入、分类、重排序（理解型任务）
- GPT 负责生成、对话、推理（生成型任务）

## 5. Base Model 的本质

Base Model（如 GPT base）特指**仅完成预训练阶段**的模型：

```
预训练（Base Model）  → 仅 next-token prediction，单向注意力
       ↓
SFT（指令微调）       → 同样是单向注意力，只是换了训练数据格式
       ↓
RLHF（偏好对齐）      → 同样是单向注意力
       ↓
ChatGPT              → 从头到尾都是单向注意力，从未引入双向注意力
```

**关键纠正**：
- SFT 没有改变模型架构，只是用"指令-回答"对数据替换预训练数据
- 双向注意力从未在 GPT 的任何阶段出现，它是架构的根本属性，不是可开关的功能
- Base Model 能"碰巧"做分析任务，靠的是规模 + 深度 + 训练数据中的模式，不是双向注意力

## 6. 当前主流 LLM 全部是纯解码器（GPT 路线）

Claude、GPT-4、Gemini、DeepSeek、LLaMA、Qwen、Mistral —— 全部是 decoder-only 架构。没有一个使用编码器+解码器的 T5/BART 路线。

各家的改良方向：
- **MoE（混合专家）**：DeepSeek V3、Gemini —— 671B 总参数但每次只激活 37B
- **MLA（多头潜在注意力）**：DeepSeek V2 —— KV Cache 压缩，推理更快
- **多模态原生**：GPT-4o、Gemini —— 直接理解图文音视频
- **超长上下文**：Gemini 100万+ token、Claude 200K token

## 7. BERT 嵌入的输出是什么

BERT 编码器输出的是**一串浮点数向量**（如 768 维）：

```
输入: "Q3 盈利是多少？"
输出: [0.023, -0.041, 0.087, ..., 0.012]   ← 768 个数字
```

- 数字本身没有可读含义，但**意思相近的文本产生相近的向量**
- 通过计算余弦相似度来判断语义相似性
- 向量数据库存储这些数字，查询时比较距离即可找到语义相关的文档

## 8. RAG 重排序

基础 RAG 的问题：向量相似 ≠ 语义相关。重排序用**交叉编码器**解决这个问题：

```
混合搜索 → Top 50 候选 → BERT 交叉编码器重排 → Top 5 精选 → GPT 生成
```

- **双编码器**（粗筛）：查询和文档独立编码，快但粗糙
- **交叉编码器**（精排）：查询和文档拼在一起编码，双向注意力，慢但精准
- 重排序用的正是 BERT 的双向注意力优势 —— 这是 BERT 帮助 GPT 生态系统的核心场景之一

## 9. RAG 完整流程

```
离线索引：文档 → 分块 → BERT 双编码器嵌入 → 写入向量数据库

在线查询：
  用户查询 → BERT 嵌入 → 混合搜索（向量 + BM25 关键词）→ Top 50
                                                          ↓
                                                BERT 交叉编码器重排 → Top 5
                                                                       ↓
                                                              构建 Prompt → GPT 生成回答
```

BERT 在 RAG 中出现两次：
1. **双编码器**：做嵌入和粗筛（快，百万级文档）
2. **交叉编码器**：做重排序（慢但准，只处理几十个候选）

## 10. RAG 准确性为什么仍然不理想

RAG 是 6 个环节的链条，每个环节都可能出错，误差层层累积：

| 环节 | 典型问题 |
|------|---------|
| 分块 | 信息被切断，嵌入时丢失上下文 |
| 嵌入 | 语义鸿沟 —— 问题和答案在向量空间中天然不在同一位置 |
| 向量检索 | HNSW 近似搜索引入误差（~5% 的正确结果可能丢失） |
| 重排序 | 交叉编码器仍可能被共享词汇误导 |
| Prompt 构建 | 噪声文档干扰，互相矛盾的信息 |
| LLM 生成 | 幻觉、推理错误、过度自信 |

即使每个环节 95% 准确率，整体：0.95⁶ = 73.5%。

结构性难题：信息不在文档库中、需要多跳推理、需要隐含知识。

## 11. 实时 RAG vs Agentic Search

| | 实时 RAG（Perplexity） | Agentic Search（Claude Code） |
|--|----------------------|-------------------------------|
| 流程 | 固定管道，查询→检索→生成 | 模型驱动循环，自主决策每一步 |
| 检索次数 | 1 次 | N 次，模型决定 |
| 模型角色 | 只负责最后生成 | 全程决策：搜什么、怎么搜、要不要再搜 |
| 工具 | 只有网页搜索 | 搜索、读文件、执行命令、调用 API…… |
| 类比 | 图书馆参考咨询台 | 私人研究助理 |

主流 AI 搜索产品（Perplexity、Google AI Overviews、Bing Copilot、Notion AI、GitHub Copilot）底层都是 RAG 或其变体，区别在于检索来源和技术细节。

## 关键术语速查

| 术语 | 一句话解释 |
|------|-----------|
| BERT | 仅编码器，双向注意力，预测被遮住的词 |
| GPT | 仅解码器，单向注意力，预测下一个词 |
| Transformer | 编码器+解码器的完整架构蓝图 |
| T5 / BART | 编码器+解码器，完整 Transformer 路线 |
| Base Model | 仅完成预训练（next-token prediction）的模型 |
| SFT | 监督微调，用指令-回答对训练，不改变架构 |
| RLHF | 人类偏好对齐，让模型输出更符合人类期望 |
| MLM | 掩码语言建模，BERT 的预训练任务 |
| 嵌入（Embedding） | 文本 → 浮点数向量，语义相近的文本向量距离近 |
| 双编码器 | 查询和文档独立编码，快但粗糙 |
| 交叉编码器 | 查询和文档拼在一起编码，慢但精准 |
| 重排序 | 用交叉编码器对候选文档重新评分 |
| RAG | 检索增强生成 —— 检索相关文档 + LLM 生成回答 |
| MoE | 混合专家，大参数但只激活部分，降低推理成本 |
