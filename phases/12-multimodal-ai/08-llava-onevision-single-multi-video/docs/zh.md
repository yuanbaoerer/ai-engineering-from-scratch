# LLaVA-OneVision：单一模型处理单图、多图与视频

> 在 LLaVA-OneVision（Li 等，2024 年 8 月）出现之前，开放 VLM 领域存在各自独立的谱系：LLaVA-1.5 处理单图，Mantis 和 VILA 等多图模型，Video-LLaVA 和 Video-LLaMA 等视频模型。每个模型都在自己的基准测试中获胜，却在其他场景中失败。LLaVA-OneVision 提出，单一课程（curriculum）可以训练出一个模型，在三种场景中均占主导地位，并且其涌现的任务迁移效应（单图技能迁移到视频、多图推理迁移到单图）超越了专家模型之和。其方法看似简单：一个在所有场景中保持恒定的视觉 token 预算，加上一个从单图到 OneVision（多图）再到视频的显式课程。本课程将解读该预算、课程以及涌现行为。

**类型：** 构建
**语言：** Python（标准库，token 预算求解器 + 课程规划器）
**前置条件：** Phase 12 · 05（LLaVA）、Phase 12 · 06（任意分辨率）
**时间：** 约 180 分钟

## 学习目标

- 设计一个在单图、多图和视频输入中保持恒定的视觉 token 预算。
- 安排一个训练课程，将技能从单图迁移到视频，且不发生灾难性遗忘。
- 解释为何在课程设计得当的情况下，单一模型在相同参数量下能击败专家模型。
- 说出 LLaVA-OneVision 报告的三种涌现能力：多摄像头推理、标记集提示（set-of-mark prompting）、iPhone 截图智能体。

## 问题背景

图像、多图和视频对模型的挑战各不相同。

单图需要高分辨率 token（AnyRes，约 2880 个视觉 token）以捕捉 OCR 和精细细节。每个样本的预算：一张图像，2880 个 token。

多图需要多张中等分辨率的图像（每张约 576 个 token），以便跨图像推理能够容纳在上下文中。每个样本的预算：4-8 张图像，每张 576 个，共 2300-4600 个 token。

视频需要多帧低分辨率的图像（池化后每帧约 196 个 token）以捕捉时间动态。每个样本的预算：8-32 帧，每帧 196 个，共 1600-6200 个 token。

如果训练独立的模型，你会选择一种预算。如果训练单一模型，你需要预算在三种场景中合理缩放，而不至于撑爆上下文。

在 OneVision 之前，默认答案是"训练一种场景，忽略其他"。Video-LLaVA 通过额外的训练阶段将视频 retrofit 到图像模型上。LLaVA-NeXT 通过 tiling 增加了多图支持。没有一个能干净利落地处理全部三种场景。

## 核心概念

### OneVision token 预算

LLaVA-OneVision 选择一个统一的视觉 token 预算，每个样本约 3000-4000 个 token，根据不同场景进行分配：

- 单图：AnyRes-9（3x3 瓦片 + 缩略图），每个瓦片 384 分辨率，729 个 patch，激进的双线性池化 2x2 → 每个瓦片 182 个。总计：9 * 182 + 182 = 1820 个 token。或 AnyRes-4，每个瓦片 729 个 = 2916 + 729。
- 多图：每张图像中等分辨率（384，无 tiling），无池化时 729 个 token。6 张图像的预算 → 4374 个 token。
- 视频：32 帧，384 分辨率，激进 3x3 双线性池化 → 每帧 81 个 token。总计：32 * 81 = 2592 个 token。

该分配保持总 token 数大致恒定。LLM 永远不会看到撑爆上下文的 batch。编码器为每种场景生成不同的几何结构，但 LLM 消耗的预算相同。

### 三阶段课程

LLaVA-OneVision 分三个阶段训练：

1. 单图 SFT（阶段 SI）。所有数据均为单图加文本。在高分辨率 AnyRes 输入上训练。这教会了感知、OCR 和细粒度理解。使用 LLaVA-NeXT 数据以及 OneVision 特定的单图数据。
2. OneVision SFT（阶段 OV）。混合单图 + 多图 + 视频（均匀采样帧）。在统一 token 预算上训练。这教会模型处理异构 batch 形状。不重置权重——从阶段 SI 继续。
3. 任务迁移（阶段 TT）。继续使用目标任务混合进行训练，通常根据产品需求更侧重多图或视频。可选的部署微调。

关键：课程顺序很重要。先训练视频或多图会导致图像性能比先训练单图更差，即使使用相同的数据。论文对此进行了显式的消融实验。

### 课程为何有效

单图训练构建了感知基础。Patch token 携带细粒度视觉特征；LLM 学习将它们与文本整合。多图和视频引入了结构性挑战（哪张图是哪张、先发生了什么），如果没有强大的感知基础，这些很难学习。

如果你从一开始就将所有场景一起训练，模型会在感知上欠拟合（每 batch 中单图数据有限），而在结构上过拟合（大量多图/视频数据）。结果：一个遵循跨图像推理模式但视觉能力浅薄的模型。

课程顺序让你从阶段 SI 获得感知强度，然后从阶段 OV 获得组合/时间推理能力，而不会丢失任何一方。

### 跨场景涌现技能

LLaVA-OneVision 论文报告了三种涌现能力：

1. 多摄像头推理。训练时分别使用多图和视频；推理时要求对多摄像头驾驶场景进行推理。模型正确整合了各个视角，尽管训练中从未见过这种确切格式。
2. 标记集提示（Set-of-mark prompting）。用户在图像中用数字标记标注物体；模型推理"标记 3 相对于标记 7 在做什么"。训练时既未见过标记也未见过标注；从空间定位 + 多图参考的组合中学习而来。
3. iPhone 截图智能体。用户提供 iPhone 屏幕截图并要求规划下一次点击。训练数据包括 UI 截图、用户工作流视频和多图前后对比。泛化到智能体用例。

这些不是训练任务；它们从课程的组合结构中涌现。

### 视觉 token 池化

Token 预算需要池化。OneVision 在 2D patch 网格上使用双线性插值：24x24 = 576 个 patch 变为 12x12 = 144（2 倍因子）或 8x8 = 64（3 倍因子）。池化在 patch 网格空间中进行，而非 token 空间，以保留局部性。

每种场景的池化因子选择本身就是一个超参数。池化越少 = 更多 token = 更丰富的表示。池化越多 = 更少 token = 能容纳更多帧/图像。

### LLaVA-OneVision-1.5

2025 年的后续工作（LLaVA-OneVision-1.5，arXiv 2509.23661）在训练数据、模型权重和代码方面"完全开放"。在某些基准测试上追平了专有模型的差距，并使该方案民主化。相同的课程，更多数据，更好的基础 LLM。架构无变化。

### 与 Qwen2.5-VL 的对比

Qwen2.5-VL（课程 12.09）做出了不同选择。它使用 M-RoPE 和动态 FPS 而非固定池化。其预算随输入缩放——1 分钟视频使用的 token 多于 5 秒视频。LLaVA-OneVision 固定预算并缩放池化。两者都有效；它们在可配置性与可预测性之间进行权衡。

## 使用它

`code/main.py` 是一个 OneVision 风格的 VLM 课程和预算规划器。给定每个样本的 token 预算和目标场景混合（例如 40% 单图、30% 多图、30% 视频），它将：

- 为每种场景分配分辨率、池化因子和帧数。
- 检查每种场景是否适合共享预算。
- 报告预期 token 数、LLM FLOPs 以及哪些场景 token 不足。
- 打印分阶段训练计划。

使用它来规划 OneVision 微调，或验证 VLM 部署的每次请求成本。

## 交付它

本课程产出 `outputs/skill-onevision-budget-planner.md`。给定目标任务分布和每个样本的预算，它输出 AnyRes 因子、每帧池化、视频帧数和课程阶段权重。每当你训练或微调统一场景 VLM 时使用它。

## 练习

1. 你的产品支持 80% 单图、10% 多图（2-4 张图像）、10% 视频（8-16 帧）。设计 token 预算。你会将不重度做多图而节省的额外预算放在哪里？

2. 阅读 LLaVA-OneVision 第 4.3 节（涌现能力）。提出一种课程可能解锁但论文未报告的第四种涌现技能。

3. 交换课程顺序——先训练多图，然后单图，然后视频。预测哪些基准测试会下降以及原因。

4. 论文报告视频基准测试仅在每样本 8 帧上训练。这能泛化到推理时的 30 秒视频吗？什么会先崩溃——token 预算还是时间推理？

5. 将 24x24 个 patch 双线性池化到 12x12 是每维 4 倍缩减。用标准库 Python 实现该池化，并验证每个 2x2 块的均值与双线性输出匹配。

## 关键术语

| 术语 | 人们怎么说 | 实际含义 |
|------|-----------|---------|
| OneVision 场景 | "单图、多图或视频" | 统一 VLM 处理的三种输入形状之一；预算在它们之间保持恒定 |
| Token 预算 | "每个样本多少 token" | LLM 在每个训练/推理样本中看到的视觉 token 总数，通常为 3000-4000 |
| 课程（Curriculum） | "训练顺序" | 阶段排序（单图 → 多图 → 视频），选择用于涌现迁移 |
| 双线性池化（Bilinear pooling） | "Token 压缩" | 对 patch 网格（2D）应用双线性插值以减少 token 数，同时保留局部性 |
| 涌现技能（Emergent skill） | "没训练过，但管用" | 推理时出现的能力，没有对应的训练数据，源于课程组合 |
| AnyRes-k | "k 瓦片设置" | k 个固定分辨率子瓦片加一个缩略图，典型 k ∈ {4, 9} |
| 任务迁移（Task transfer） | "跨场景泛化" | 通过共享主干，在单图上学习的技能应用到视频（反之亦然） |
