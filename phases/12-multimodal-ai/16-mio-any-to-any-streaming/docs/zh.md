# MIO 与 Any-to-Any 流式多模态模型

> GPT-4o 推出了一款大多数开源模型无法复制的产品：一个能够实时听到语音、看到视频并实时回话的 Agent。到2024年底，开源生态的回应是 MIO（Wang 等，2024年9月）。MIO 将文本、图像、语音和音乐进行 token 化，在一个因果 Transformer 上训练交错序列，并实现任意模态到任意模态的生成。AnyGPT（Zhan 等，2024年2月）是概念验证；MIO 是其规模化版本；Unified-IO 2（Allen AI，2023年12月）则是具备视觉 + 动作 grounding 的姊妹方案。本课解读 any-to-any 范式——四种 tokenizer、一个 Transformer、支持流式解码。

**类型：** 学习
**语言：** Python（标准库，四模态 token 分配器 + 流式解码循环）
**前置知识：** Phase 12 · 11（Chameleon），Phase 6（语音与音频）
**时长：** 约120分钟

## 学习目标

- 设计一个共享词表，容纳文本、图像、语音和音乐 token 且互不冲突。
- 比较 SEED-Tokenizer（图像）与 SpeechTokenizer residual-VQ（语音）在压缩率与重建质量之间的权衡。
- 解释构建 any-to-any 生成的四阶段课程。
- 列举三种开源 any-to-any 方案及其主要权衡：MIO、AnyGPT、Unified-IO 2。

## 问题背景

统一多模态模型说起来容易，规模化构建却很难。2024年之前的大多数 "any-to-any" 系统都是流水线式的：视觉模型 → 文本表示 → 语音模型 → 音频。每一步都会丢失信息、增加延迟并复杂化训练。GPT-4o 的演示视频展示了一个单模型替代方案，响应时间低于一秒；开源系统则落后数月。

工程挑战：

- Tokenizer 必须覆盖每种模态，压缩到足以无损重建的程度，并以 Transformer 能够处理的速率产出 token。
- 单个词表必须为文本（32k+）、图像（16k+）、语音（4k+）、音乐（8k+）分配空间。最少需要四万多个条目。
- 训练数据必须覆盖每一种输入-输出对（文本→图像、图像→语音、语音→图像等），否则模型必须具备组合能力。
- 推理必须足够快地流式输出 token，以满足对话延迟要求（<500ms 首音频字节时间）。

## 核心概念

### 四种模态的四种 Tokenizer

MIO 的 tokenizer 栈：

- 文本：标准 BPE，词表约 32000。
- 图像：SEED-Tokenizer（2023）—— 量化 VAE 配合离散码本，4096 个条目，每幅图像 32×32 个 token。
- 语音：SpeechTokenizer residual-VQ（2023）—— 将 16kHz 波形编码为 8 个层级码本；第一层是粗粒度内容，后续层级添加韵律和说话人身份信息。
- 音乐：类似的 residual-VQ（Meta 的 MusicGen / Encodec 家族），4-8 个码本。

每种模态产出整数 token。这些 token 在共享词表中获得互不相交的 ID 区间：

```
text:   0..31999
image:  32000..36095  (4096 个图像 token)
speech: 36096..40191  (4096 个语音基础 token，外加残差层)
music:  40192..48383  (8192 个音乐 token)
sep:    48384..48390  (<image>, <speech>, <music>, </...> 等)
```

总计：约 48k 词表。输入嵌入层和输出投影层覆盖全部区间。

### 流式解码

语音生成使用 residual-VQ。Transformer 预测基础（第0层）语音 token；并行解码的残差量化器预测后续层级。每个第0层 token 对应约 16kHz 下 50ms 的音频。

流式模式：

1. 用户对着麦克风说话；实时音频 tokenizer 每 50ms 输出语音 token。
2. MIO 在 token 到达时即时消费（prompt 预填充 + 增量前向传播）。
3. 输出 token 在生成时流式输出；并行语音解码器以约 50-150ms 的延迟将其转换为音频采样。
4. 首音频字节时间：MIO 论文中约 300-500ms，接近 GPT-4o 的约 250ms。

Mini-Omni（arXiv:2408.16725）、GLM-4-Voice（arXiv:2412.02612）和 Moshi（arXiv:2410.00037）是互补的流式语音 LLM 设计。Moshi 尤其能在单张 GPU 上实现 160ms 的往返延迟。

### 四阶段课程

MIO 的训练课程：

1. 阶段 1 —— 对齐。大规模模态配对语料：文本-图像、文本-语音、文本-音乐。每对使用各自的词表区间。训练共享词表。
2. 阶段 2 —— 交错。多模态交错文档（带图像 + 视频的博客、带转录稿的播客等）。训练跨模态上下文。
3. 阶段 3 —— 语音增强。额外的音频数据以提升语音质量，同时不损失文本能力。
4. 阶段 4 —— SFT。跨模态的指令微调：VQA、图像描述、旁白、语音到语音对话。

跳过任一阶段都会削弱特定能力：跳过阶段 2，模型失去跨模态上下文；跳过阶段 3，语音质量变差。

### 视觉思维链（Chain-of-visual-thought）

MIO 引入了视觉思维链：模型将中间图像 token 作为推理步骤输出。对于"猫在爬树吗？"这个问题，模型：

1. 输出 `<image>` token 渲染场景（来自输入图像或草图）。
2. 输出文本分析该草图。
3. 输出最终答案。

渲染的中间图像充当草稿纸。在空间推理任务上基准测试表现提升。这一思路与文本推理中的思维链（Chain-of-Thought）相呼应。

### Any-to-Any 领域的竞争者

- AnyGPT（arXiv:2402.12226）：4 种模态（文本、图像、语音、音乐），类似设计。
- Unified-IO 2（arXiv:2312.17172）：增加视觉动作输出、深度图、法线图。任务多样性更高，规模更小。
- NExT-GPT（arXiv:2309.05519）：LLM + 模态特定的扩散解码器。非单模型方案。
- CoDi（arXiv:2305.11846）：可组合扩散；通过共享隐空间实现 any-to-any。

MIO 最接近纯 token 化的 any-to-any。AnyGPT 是其概念上的先驱。

### 延迟预算

对于对话产品，每个组件的延迟都至关重要：

- 麦克风到音频 token：约 50ms。
- 预填充（音频 token + 历史）：8B 模型上约 100ms。
- 首个输出 token：约 50ms。
- 并行 residual-VQ + 语音解码器：约 100-150ms。

首音频字节时间总计：最少约 300ms。GPT-4o 宣称约 250ms。Moshi 宣称 160ms。MIO/AnyGPT 在公开基准测试中处于 400-600ms 范围。

### 为什么 Any-to-Any 仍然困难

即便到了2026年，开源 any-to-any 模型在两个维度上仍落后于闭源模型：

- 语音质量。Residual-VQ tokenizer 是有损的；对话语音听起来比 ElevenLabs 级别的声音更机械。
- 跨模态推理。让模型"唱出你所看到的"仍然比纯视觉任务更容易失败。

这些都是开放的研究问题。Qwen3-Omni（第 12.20 课）是2025年最先进的开源尝试。

## 练习题

1. 你的产品接受语音输入并返回语音输出。端到端延迟预算目标应该是多少？列出消耗时间的各个组件。

2. SpeechTokenizer residual-VQ 使用 8 个码本。说明为什么必须并行解码残差层级（而非顺序解码），以及它能带来多少延迟节省。

3. 你的词表有 32k 文本 + 4k 图像 + 4k 语音。再增加 8k 音乐和约 10 个分隔符。在隐藏维度 4096 下，嵌入矩阵的参数成本是多少？

4. 视觉思维链输出一张中间图像。哪些问题能从中受益？哪些问题会因额外 token 而受损？

5. 阅读 Moshi（arXiv:2410.00037）。描述其"内心独白"技术，并与 MIO 的视觉思维链进行比较。

## 关键术语

| 术语 | 人们的说法 | 实际含义 |
|------|-----------|---------|
| Any-to-any | "多模态输入/输出" | 一个单模型，可在任意方向上接受和生成文本、图像、语音和音乐 |
| Residual-VQ | "语音 tokenizer 栈" | 多码本 token 化，每一层添加信息；基础层是内容，后续层是韵律 |
| SEED-Tokenizer | "图像编码" | MIO 使用的离散图像 tokenizer，具有 4096 条目的码本 |
| Chain-of-visual-thought | "视觉草稿纸" | 模型在给出最终答案前，生成一张中间图像作为推理步骤 |
| Time-to-first-audio-byte | "TTFAB" | 从用户语音到首个音频输出的延迟；<500ms 才有对话感 |
| Four-stage curriculum | "训练配方" | 对齐 → 交错 → 语音增强 → SFT，按此顺序 |
