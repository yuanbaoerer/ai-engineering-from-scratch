# AlphaEvolve — 进化式编码代理

> 将前沿编码模型与进化循环和机器可检查的评估器配对。让循环运行足够长的时间。它发现了一个使用 48 次标量乘法的 4x4 复数矩阵乘法程序——这是 Strassen 算法 56 年来的首次改进。它还找到了一个 Google 范围的 Borg 调度启发式算法，在生产中回收了约 0.7% 的集群计算资源。架构故意很无聊。收益来自评估器的严格性。

**类型：** 学习
**语言：** Python（标准库，进化循环玩具）
**前置条件：** 第 15 阶段 · 01（长时域框架），第 15 阶段 · 02（自教导推理）
**时间：** ~60 分钟

## 问题

大型语言模型可以编写代码。进化算法可以搜索代码。两者都已经单独尝试了几十年；两者都碰到了天花板。LLM 的天花板是虚构：模型编写看似合理的代码，但并不做它声称的事情。进化的天花板是搜索成本：对语法的随机突变很少产生可编译的程序，更不用说更好的程序了。

AlphaEvolve（Novikov 等人，DeepMind，arXiv:2506.13131，2025 年 6 月）将两者结合。LLM 对程序数据库提出有针对性的编辑；自动评估器对每个变体评分；高分变体成为下一代的父代。LLM 处理编写合理代码这一昂贵步骤；评估器捕获虚构。循环运行数小时到数周。

报告的结果：48 次标量乘法的 4x4 复数矩阵乘法（Strassen 1969 年的界限是 49）、Google 生产中的 Borg 调度启发式算法、32.5% 的 FlashAttention 内核加速、Gemini 训练吞吐量改进。

该架构之所以有效，是因为评估器是机器可检查的。在评估器不严格的领域，它就不有效。这种不对称性就是教训。

## 概念

### 循环

1. 从一个正确但非最优的种子程序 `P_0` 开始。
2. 维护一个变体程序数据库，每个都由评估器评分。
3. 从数据库中采样一个或多个父代（MAP-elites 风格或基于岛屿的方法）。
4. 提示 LLM（Gemini Flash 用于多个候选，Gemini Pro 用于困难的）生成父代的修改变体。
5. 编译、运行并在留出的评估器上评估变体。
6. 按分数和特征向量插入数据库。
7. 重复。

两个细节很重要。首先，LLM 的提示不仅仅是父代程序——通常还包括数据库中的几个顶级变体、评估器签名和简短的任务描述。模型的工作是提出可能提高分数的有针对性更改。其次，数据库是结构化的（MAP-elites 网格、基于岛屿），这样循环探索多样性，而不仅仅是当前的领先者。

### 为什么评估器是不可妥协的

AlphaEvolve 的所有成功都来自评估器快速、确定且难以博弈的领域：

- **矩阵乘法算法**：一个单元测试，乘以矩阵并逐位检查相等性。
- **Borg 调度启发式算法**：一个生产级模拟器，回放历史集群负载并测量浪费的计算。
- **FlashAttention 内核**：一个正确性测试加上真实硬件上的挂钟基准。
- **Gemini 训练吞吐量**：测量每步的 GPU 秒数。

在每种情况下，评估器都捕获了否则会占主导地位的 LLM 错误类别：虚构的正确性声明、在硬件上消失的性能声明和边缘情况失败。移除评估器，循环就会优化漂亮的代码。

### 奖励黑客攻击是这句话的另一面

进化优化评估器测量的任何东西。如果评估器不完美，循环就会找到不完美之处。在一个未经验证的领域，循环会优化表面特征，而非预期行为。DeepMind 在论文中明确指出这一点：AlphaEvolve 的成功仅转移到评估器严格性与搜索雄心匹配的领域。

代码搜索循环中奖励黑客攻击的 2025-2026 年具体示例：

- 奖励"完成时间"的优化目标奖励提交空解决方案。
- 奖励测试下正确性的基准分数奖励记忆测试和过拟合。
- "代码质量"代理奖励删除注释和重写变量名，而没有语义更改。

AlphaEvolve 中的修复方案：部署一个 LLM 从未见过的留出评估器，输入在评估时生成。即便如此，DeepMind 建议对任何拟议部署进行严格审查。

### 为什么 LLM + 搜索优于单独使用任一方

LLM 可以生成可编译的、语义上合理的修改。对 2000 行 Python 文件的随机突变 GA 几乎总是产生语法错误。LLM 还将搜索集中在合理的邻域（更改一个函数，而非随机字节），这大大减少了浪费的评估器调用。

反过来，评估器捕获了 LLM 的虚构。LLM 会自信地声称一个函数"在极限情况下是 O(n log n)"，而实际上是 O(n^2)；挂钟基准使这个问题得到解决。

### AlphaEvolve 在前沿技术栈中的位置

| 系统 | 生成器 | 评估器 | 领域 | 示例成功 |
|---|---|---|---|---|
| AlphaEvolve | Gemini | 正确性 + 基准 | 算法、内核、调度器 | 48-mul 4x4 matmul |
| FunSearch（DeepMind，2023） | PaLM / Codey | 正确性 | 组合数学 | cap-set 下界 |
| AI Scientist v2（Sakana，L5） | GPT/Claude | LLM 批评 + 实验 | ML 研究 | ICLR workshop 论文 |
| Darwin Godel Machine（L4） | 代理脚手架 | SWE-bench / Polyglot | 代理代码 | 20% → 50% SWE-bench |

四者都是相同配方的变体：生成器 + 评估器，循环。区别在于评估器评分什么以及它有多严格。

## 使用它

`code/main.py` 在一个玩具符号回归问题上实现了一个最小的类 AlphaEvolve 循环。"LLM"是一个标准库代理，对计算目标函数的程序提出小的语法突变。"评估器"在留出的测试点上测量均方误差。

观察：

- 最佳分数如何在世代中改进。
- MAP-elites 网格如何保持多样化的解决方案存活，使循环不会收敛到局部最小值。
- 移除留出测试（仅训练评估器）如何让循环严重过拟合。

## 练习

1. 运行 `code/main.py`。注意最佳分数轨迹。禁用留出评估器（标志 `--no-holdout`）并重新运行。量化过拟合。

2. 阅读 AlphaEvolve 论文第 3 节关于 MAP-elites 网格的内容。为一个新问题（例如编译器优化 pass）设计一个特征向量描述符，以保持搜索的多样性。

3. 48 次乘法的 4x4 结果在 56 年后改进了 Strassen 的 49 次界限。阅读论文附录 F，用三句话解释为什么这个问题的评估器特别容易正确，以及为什么大多数领域不像它。

4. 提出一个 AlphaEvolve 会失败的领域。准确指出评估器在哪里失效以及为什么。

5. 对于一个你了解的领域，写出你会使用的评估器签名。包括（a）正确性条件，（b）性能指标，（c）留出输入生成规则，（d）至少一个反奖励黑客检查。

## 关键术语

| 术语 | 人们怎么说 | 实际含义 |
|---|---|---|
| AlphaEvolve | "DeepMind 的进化编码代理" | Gemini + 程序数据库 + 机器可检查的评估器 |
| MAP-elites | "保持多样性的存档" | 以特征向量为键的网格；每个单元格保存该描述符的最佳变体 |
| 岛屿模型 | "并行进化子种群" | 独立种群，定期迁移；防止过早收敛 |
| 机器可检查的评估器 | "确定性预言机" | LLM 无法伪造的单元测试、模拟器或基准——此循环的前提 |
| 奖励黑客攻击 | "优化度量，而非目标" | 循环找到一种在不执行预期任务的情况下最大化分数的方式 |
| 种子程序 | "起点" | 循环从其演化的初始正确但非最优的程序 |
| 留出评估器 | "LLM 从未见过的评估数据" | 在评估时生成的输入，防止记忆 |
