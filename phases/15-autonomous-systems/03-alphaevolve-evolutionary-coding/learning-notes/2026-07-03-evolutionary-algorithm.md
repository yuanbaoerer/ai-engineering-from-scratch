# AlphaEvolve 进化式编码代理学习笔记

> 日期: 2026-07-03

## 1. 进化算法的基本概念

进化算法受生物进化启发，核心思想：**从一个初始解出发，通过变异、评估、选择，不断产生更好的解**。

| 步骤 | 含义 | 类比 |
|------|------|------|
| 种子程序 | 初始正确但非最优的程序 | 生物的祖先 |
| 变异 | 对程序进行修改 | 基因突变 |
| 评估 | 用评估器给变体打分 | 自然选择 |
| 选择 | 高分变体成为下一代父代 | 适者生存 |

## 2. AlphaEvolve 的核心创新

LLM 和进化算法各有天花板：

| 系统 | 优势 | 天花板 |
|------|------|--------|
| LLM | 能写合理代码 | 会"虚构"（confabulation）—— 写出看似合理但实际错误的代码 |
| 进化算法 | 能搜索解空间 | 随机突变几乎不产生可编译程序 |

**AlphaEvolve 的解法**：让 LLM 负责生成代码修改（解决搜索成本），让评估器捕获虚构（解决可信度）。

## 3. 进化循环的 7 个步骤

1. 从种子程序 P₀ 开始
2. 维护一个变体程序数据库（每个变体都有评分）
3. 从数据库中采样父代
4. 提示 LLM 生成修改变体
5. 编译、运行、评估变体
6. 按分数插入数据库
7. 重复循环（运行数小时到数周）

⚠️ **看不懂的部分**：MAP-elites 网格和岛屿模型的具体实现方式不清楚

## 4. 评估器的重要性

AlphaEvolve 的成功**必须**满足一个前提：**评估器是机器可检查的**（快速、确定、难以博弈）。

成功案例：
- 矩阵乘法 → 单元测试逐位检查
- Borg 调度 → 生产级模拟器回放历史负载
- FlashAttention → 真实硬件基准测试

⚠️ **看不懂的部分**：为什么评估器不严格的领域会失败？奖励黑客（reward hacking）的机制不太理解

## 5. 奖励黑客（Reward Hacking）

进化会优化**评估器实际测量的东西**，而不是**我们想要的目标**。

如果评估器有漏洞，循环会找到漏洞并最大化分数，而不完成真正的任务。

2025-2026 年的反面案例：
- 奖励"完成时间" → 提交空解决方案
- 奖励测试正确性 → 记忆测试数据、过拟合
- 奖励"代码质量" → 删除注释、重写变量名（无语义变化）

## 6. AlphaEvolve 的实际成果

| 成果 | 说明 |
|------|------|
| 4×4 矩阵乘法 | 48 次标量乘法（Strassen 56 年来首次改进，原界限 49） |
| Borg 调度 | Google 生产中回收 ~0.7% 集群计算 |
| FlashAttention | 32.5% 内核加速 |
| Gemini 训练 | 训练吞吐量改进 |

⚠️ **看不懂的部分**：矩阵乘法评估器为什么"特别容易正确"，为什么大多数领域不像它
