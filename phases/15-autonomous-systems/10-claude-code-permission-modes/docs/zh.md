# Claude Code 作为自主代理：权限模式与 Auto Mode

> Claude Code 暴露七种权限模式。"plan"在每次动作前询问，"default"仅对有风险的动作询问，"acceptEdits"自动批准文件写入但仍确认 shell 执行，"bypassPermissions"批准一切。Auto Mode（2026 年 3 月 24 日）用两阶段并行安全分类器替代逐动作审批：单 token 快速检查在每个动作上运行；被标记的动作触发思维链深度审查。动作预算通过 `max_turns` 和 `max_budget_usd` 执行。Auto Mode 作为研究预览发布——Anthropic 已明确表示分类器本身不充分。

**类型：** 学习
**语言：** Python（标准库，两阶段分类器模拟器）
**前置条件：** 第 15 阶段 · 01（长时域代理），第 15 阶段 · 09（编码代理全景）
**时间：** ~45 分钟

## 问题

你机器上的自主编码代理是一个独特的安全类别。攻击面是代理能触及的一切——文件系统、网络、凭据、剪贴板、任何浏览器标签、任何打开的终端。Bruce Schneier 和其他人公开指出：计算机使用代理不是聊天机器人的"功能更新"，它们是具有新型风险特征的新工具。

Claude Code 的权限系统是 Anthropic 的答案。不是一个"自主/非自主"开关，而是七种模式跨越能力阶梯：plan → default → acceptEdits → … → bypassPermissions。每种模式是速度和逐动作审查之间的不同权衡。Auto Mode（2026 年 3 月）添加了两阶段分类器，将分类器判断安全的动作的审批移出用户关键路径，同时为分类器标记的动作保留审查层。

工程问题：这个系统捕获什么，遗漏什么，给定任务实际需要哪种模式？

## 概念

### 七种权限模式

| 模式 | 行为 | 何时使用 |
|---|---|---|
| `plan` | 代理提议计划；用户批准整个计划；每个动作在执行前审查 | 不熟悉的任务；生产相关代码；第一次在仓库上使用代理 |
| `default` | 代理运行动作；对任何"有风险"动作（shell exec、破坏性操作、网络调用）提示用户 | 大多数交互式编码会话 |
| `acceptEdits` | 文件写入自动批准；shell exec 和网络调用仍提示 | 跨多个文件的重构 |
| `acceptExec` | shell 命令在策划白名单内自动批准；写入自动批准 | 紧密内循环，每个 shell 命令是 `npm test` 或类似 |
| `autoMode` | 两阶段安全分类器；标记的动作升级审查 | 受限工作空间中的长时域无人值守运行 |
| `yolo` | 跳过大多数提示；仍运行工具白名单/黑名单 | 临时沙箱、CI 作业、研究脚本 |
| `bypassPermissions` | 批准一切 | 文档记录为"仅在你愿意丢弃的临时容器内" |

（以上名称与公开 Claude Code 文档匹配；"yolo"是非正式简写。）

### Auto Mode 一页概览

Auto Mode（2026 年 3 月 24 日推出）是第一个将逐动作审批委托给模型的权限模式。结构：

1. **阶段 1 — 单 token 分类器。** 在每个拟议动作上运行。低成本。返回"安全"或"标记"。设计为与主代理循环并行运行，这样批准的动作不会排队等待。
2. **阶段 2 — 二级策略/安全审查。** 仅在标记的动作上运行。对动作、会话当前状态和声明任务执行集中的策略和安全评估。如果置信度低则升级到用户 HITL。

预算控制与分类器并列：

- `max_turns` — 会话中的总迭代次数。
- `max_budget_usd` — 中止会话的美元上限。
- 每工具的动作计数限制（不超过 N 次 `WebFetch` 调用等）。

### 系统捕获什么

- 直接对工具输入的提示注入，其中注入指令映射到已知有风险的动作形状。
- 重复工具循环——分类器可以看到动作 N+1 几乎与动作 N 相同，连续五次。
- 在否则仅文件编辑的会话中明显超出范围的 shell 命令。

### 系统可能遗漏什么

- **微妙的提示注入**，调制行为而不产生单个标记动作。间接提示注入不是完全可修补的漏洞（OpenAI preparedness 负责人，2025 年，关于浏览器代理——见第 11 课）。
- **语义级异常行为。** 每个单独动作看起来安全，而组合轨迹有害。分类器判断动作；它不重新推导用户意图。
- **通过合法渠道的数据泄露。** 将数据写入你拥有的文件，然后 `git push` 到公共仓库，是一系列允许的动作，其组合是问题。

### 研究预览框架

Anthropic 将 Auto Mode 作为研究预览发布。文档明确指出分类器是一个层，而非解决方案：用户被期望将 Auto Mode 与预算、白名单、隔离工作空间和轨迹审计（第 12-16 课）结合使用。预览框架也反映了文档中记录的评估与部署差距（第 1 课）——通过离线评估的分类器在真实会话中可能表现不同，用户上下文模糊。

### 这个阶梯在你工作流中的位置

- 不熟悉的任务：从 `plan` 开始。阅读计划比回滚坏运行更便宜。
- 已知重构：`acceptEdits` 节省大量确认点击。
- 无人值守后台运行：`autoMode` 仅在你已测量爆炸半径的工作空间内（无凭据、无生产挂载、无你未选择的出口）。
- 临时容器：`yolo` / `bypassPermissions` 仅当容器和其凭据是一次性时才可接受。

## 使用它

`code/main.py` 模拟两阶段分类器。阶段 1 是对拟议动作的低成本关键词规则；阶段 2 是较慢的多规则审查器。驱动器输入一个短的合成轨迹（安全动作、提示注入尝试、重复循环），显示分类器捕获和遗漏的地方。

## 交付它

`outputs/skill-permission-mode-picker.md` 将任务描述匹配到正确的权限模式、预算上限和所需隔离。

## 练习

1. 运行 `code/main.py`。哪种合成动作类型从未被阶段 1 标记但总是被阶段 2 捕获？哪种两者都捕获不到？

2. 扩展阶段 1 规则集以捕获特定已知有形状（例如 `curl $ATTACKER/exfil`）。在良性动作样本上测量假阳性率。

3. 阅读 Anthropic 的"How the agent loop works"文档。列出代理在 `default` 模式下默认触及的每个外部状态。哪些你需要在无人值守运行 `autoMode` 前单独门控？

4. 设计一个 24 小时无人值守运行预算：`max_turns`、`max_budget_usd`、每工具上限、白名单。证明每个数字的合理性。

5. 描述一个轨迹，其中每个单独动作都被阶段 1 和阶段 2 批准，但组合行为不对齐。（第 14 课涵盖急停开关和金丝雀令牌如何解决这个问题。）

## 关键术语

| 术语 | 人们怎么说 | 实际含义 |
|---|---|---|
| 权限模式 | "代理能做多少" | 控制逐动作审批的七种命名策略之一 |
| plan 模式 | "做任何事之前询问" | 代理写计划；用户在执行前批准 |
| acceptEdits | "让它写文件" | 文件写入自动批准；shell exec 仍提示 |
| autoMode | "自动审批" | 两阶段安全分类器；标记的动作升级 |
| bypassPermissions | "完全 YOLO" | 批准一切；用于临时容器 |
| 阶段 1 分类器 | "快速 token 检查" | 对拟议动作的单 token 规则；并行运行 |
| 阶段 2 分类器 | "深度审查" | 对标记动作的思维链推理 |
| 研究预览 | "非 GA" | Anthropic 对故障模式仍在映射中的功能的框架 |
