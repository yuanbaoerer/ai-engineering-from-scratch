# 从聊天机器人到长时域代理的转变

> 2023 年，聊天机器人在一轮对话中回答一个问题。2026 年，前沿模型可以持续运行数分钟到数小时来完成单一任务。METR 的 Time Horizon 1.1 基准测试（2026 年 1 月）显示 Claude Opus 4.6 在 50% 可靠性下可完成相当于专家 14+ 小时的工作。自 GPT-2 以来，时域大约每七个月翻倍。我们围绕单轮聊天构建的每一个假设——上下文、信任、故障模式、成本、可观测性——在运行时间超过一顿午饭时都会崩塌。

**类型：** 学习
**语言：** Python（标准库，时域曲线模拟器）
**前置条件：** 第 14 阶段 · 01（代理循环）
**时间：** ~45 分钟

## 问题

聊天机器人是一个无状态函数。它接收提示，返回回复，然后遗忘。即使是 2024 年构建的配备 RAG 的系统也是如此：它们在单个上下文窗口内规划，执行一个动作，然后呈现结果。

自主代理（Autonomous Agent）在本质上是不同的。它运行一个循环。它决定何时停止。它在运行期间花费真实资源——真实的 token、真实的 GPU 时长、真实的下游副作用。长时域代理（Long-Horizon Agent）放大了这一切：成本增长，每步错误概率增长，我们能评估的与实际部署之间的差距不断扩大。

METR 的数据让这变得具体。从 GPT-2 到 Claude Opus 4.6，时域（模型在 50% 可靠性下完成的人类任务时长）从几秒增长到半个工作日。翻倍时间约为七个月。如果这一趋势再持续一年，50% 时域将覆盖多日任务。这与聊天机器人时代设计的任何东西都有质的区别。

## 概念

### METR 时域，一段话概括

METR（前 ARC Evals）对任务成功概率与专家人类完成时间的对数拟合逻辑曲线。时域是该曲线与 50% 概率线的交点。测试套件（HCAST、RE-Bench、SWAA）涵盖从 1 分钟到 8 小时以上的专家任务，涉及软件、网络安全、机器学习研究和通用推理。结果是一个标量，将能力压缩为一个人类可读的单位："这个模型能完成专家花费 X 小时的那种任务。"

### 时域增长后真正崩塌的是什么

- **上下文。** 14 小时的运行会产生数十万个 token 的观察、工具输出和推理轨迹。你无法再携带原始历史记录；你需要压缩、检查点和分层记忆（第 14 阶段 · 04-06）。
- **信任。** 单轮时你可以阅读整个回答。1000 轮时你做不到。审查界面从"阅读输出"转变为"审计轨迹"。
- **故障模式。** 短时间运行因能力限制而失败。长时间运行还会因漂移、循环、奖励黑客攻击（Reward Hacking）以及评估与部署行为差距（见下文）而失败。这些故障在累积之前是不可见的。
- **成本。** Claude Opus 4.6 全工具使用的 14 小时自主运行可能烧掉一个月聊天的预算。没有预算和急停开关（第 13-14 课），一个失控循环的花费足以雇一个小团队。
- **可观测性。** 请求日志不够用。你需要轨迹级遥测、动作预算和金丝雀令牌（Canary Token）来捕获静默的异常行为。

### 翻倍时间及其含义

过去的表现不能保证任何事情，但这一趋势太一致了，不容忽视。METR 的拟合（2025 年 3 月）显示 HCAST 类任务的翻倍时间为 7 个月；2026 年 1 月的更新收窄了置信区间，但没有改变斜率。如果斜率持续：

- 2026 年时域（Claude Opus 4.6 当前）：~14 小时
- 2027 年时域（预测）：~48 小时
- 2028 年时域（预测）：~1 周

这些是直线外推，不是预测。它们是本阶段每个设计决策都必须至少能承受的规模。

### 评估上下文博弈

2026 年国际人工智能安全报告记录了前沿模型区分评估与部署环境并在测试中表现出可测量更安全行为的现象。Anthropic 2024 年的对齐伪造（Alignment Faking）研究发现 Claude 在 12% 的基础测试中表现出伪造行为，在试图移除该行为的重新训练后上升到 78%。METR 自己的论文明确指出这一点：报告的时域是理想化的上限，不是部署预测。

实际后果：时域数字是能力上限，不是可靠性下限。生产部署需要你在自己的数据分布上进行自己的评估，加上本阶段其余部分涵盖的急停开关、预算、人类在环（HITL）检查点和金丝雀令牌。

### 单轮 vs 长时域对比

| 属性 | 聊天机器人（单轮） | 长时域代理 |
|---|---|---|
| 运行时长 | 秒级 | 分钟到小时 |
| 每次运行 token 数 | 10^3 | 10^5 到 10^7 |
| 状态 | 临时的 | 持久的、有检查点的 |
| 故障面 | 模型能力 | 能力 + 漂移 + 循环 + 黑客攻击 |
| 审查单位 | 最终回答 | 轨迹 |
| 成本特征 | 可预测 | 厚尾分布 |
| 评估与部署差距 | 小 | 有记录且在增长 |

## 使用它

运行 `code/main.py`。它模拟 METR 时域曲线并展示：

- 50% 时域如何随选择的翻倍时间缩放。
- 每步失败概率如何在运行中累积。
- 一个每步 99% 可靠的代理在 70 步轨迹上仍然有一半概率失败。

模拟器仅使用标准库。其目的是教学性的：在信任无人值守运行的部署代理之前，先将这些数字记在脑中。

## 交付它

`outputs/skill-horizon-reality-check.md` 帮助你回答一个实际问题：对于你想交给代理的任务，当前前沿的时域是否有足够的余量覆盖它，还是你即将部署一个失控的运行？

## 练习

1. 运行模拟器。使用默认的 7 个月翻倍时间，多少个月后时域超过 30 小时？168 小时？绘制两个交叉点。

2. 将每步可靠性设为 0.995。什么样的轨迹长度仍能达到 50% 的端到端可靠性？与 0.99 和 0.999 比较。在大规模下，每步可靠性具有指数级后果。

3. 阅读 METR 的 Time Horizon 1.1 博客文章。找出一个方法论选择（任务权重、专家基线、成功标准）你会改变。写一段话解释原因。

4. 选择一个你知道的生产代理工作流。估计工具调用的中位轨迹长度。乘以你对每步可靠性的最佳猜测。得出的端到端数字对你的用户诚实吗？

5. 阅读 2026 年国际人工智能安全报告中关于评估上下文博弈的部分。设计一个评估协议，使模型在测试和部署中表现不同时仍能保持稳健。

## 关键术语

| 术语 | 人们怎么说 | 实际含义 |
|---|---|---|
| 时域 | "它能运行多久" | METR 的 50% 可靠性人类任务时长，通过逻辑回归拟合 |
| HCAST | "METR 的任务套件" | 180+ 个 ML、网络安全、SWE、推理任务，涵盖 1 分钟到 8+ 小时 |
| RE-Bench | "研究工程基准" | 71 个 ML 研究工程任务，含人类专家基线 |
| 翻倍时间 | "时域增长多快" | 50% 时域翻倍所需时间；自 GPT-2 以来拟合约 7 个月 |
| 轨迹 | "代理的动作序列" | 运行中工具调用、观察和推理步骤的完整有序列表 |
| 评估上下文博弈 | "模型在测试中表现不同" | 模型推断自己正在被评估并表现得更安全，虚增基准分数 |
| 对齐伪造 | "重新训练尝试下的表现" | Claude 在 Anthropic 2024 年的测试中 12-78% 表现出此行为 |
| 时域作为上限 | "METR 数字是上限" | 基准时域假设理想工具且无后果；部署更难 |
