# AI Scientist v2 — Workshop 级自主研究

> Sakana 的 AI Scientist v2（Yamada 等人，arXiv:2504.08066）运行完整的研究循环：假设、代码、实验、图表、撰写、投稿。它是第一个生成的论文在 ICLR 2025 workshop 上通过同行评审的系统。独立评估（Beel 等人）发现 42% 的实验因编码错误失败，文献综述经常将已有概念错误标记为新颖。Sakana 自己的文档警告该代码库执行 LLM 编写的代码，建议使用 Docker 隔离。这两个方面都是重点。

**类型：** 学习
**语言：** Python（标准库，研究循环状态机玩具）
**前置条件：** 第 15 阶段 · 03（AlphaEvolve），第 15 阶段 · 04（DGM）
**时间：** ~60 分钟

## 问题

研究是一个开放式任务。与 AlphaEvolve 的算法搜索或 DGM 的基准约束自修改不同，研究结果没有机器可检查的正确性标准。论文由评审人评判，而非单元测试。这使得循环更难闭合——但如果闭合就更有价值，因为研究是复合进步的所在。

AI Scientist v1（Sakana，2024）通过从人类编写的模板开始闭合了循环。LLM 在固定脚手架内填充实验。AI Scientist v2（Yamada 等人，2025）通过使用带有视觉语言模型批评循环的代理树搜索（Agentic Tree Search）消除了模板要求。该系统生成想法、实现实验、产生图表、撰写论文，并根据评审反馈迭代。

同行评审结果：一篇 v2 生成的论文在 ICLR 2025 workshop 上被接受（已披露）。独立评估结果：该系统远非可靠。两者都属实。

## 概念

### 架构

1. **想法生成。** LLM 根据主题和先前文献提出研究想法。v1 使用模板；v2 在假设空间上使用代理搜索。
2. **新颖性检查。** 文献检索步骤检查该想法是否已被发表。这是 Beel 等人的评估发现错误标记的步骤——已有方法经常被归类为新颖。
3. **实验计划。** 代理起草实验协议并编写代码。
4. **执行。** 代码在沙箱中运行。失败被反馈到重试循环中。在 Beel 等人的测量中，42% 的实验在此阶段因编码错误失败。
5. **图表生成。** 视觉语言模型读取生成的图表并重写以提高清晰度。这是 v2 的关键技术添加。
6. **撰写。** LLM 起草论文，与内部评审人迭代。
7. **可选：投稿。** 论文被提交到会议。

### workshop 接受结果的含义

一篇 v2 生成的论文通过了 ICLR 2025 workshop 的同行评审。作者向程序委员会披露了论文的来源。接受是一个数据点；它不是声称该系统"做研究"的许可证。

重要背景：workshop 论文的标准低于主会议论文。同行评审有噪声；在任何给定日期，一小部分投稿会被接受。一次成功是概念验证，而非可靠性声明。Nature 2026 年的论文记录了端到端循环，并且它本身由人类研究者共同撰写；它不是"系统写了一篇 Nature 论文"。

### 独立评估发现了什么

Beel 等人（arXiv:2502.14297）进行了外部评估。主要发现：

- **实验失败。** 42% 的实验因编码错误失败（错误导入、形状不匹配、未定义变量）。重试循环捕获了一些，但不是全部。
- **新颖性错误标记。** 文献检索步骤经常将已有概念标记为新颖。这是研究领域的幻觉等价物。
- **展示质量差距。** 视觉语言图表批评产生了出版级视觉效果，掩盖了底层实验的弱点。

最后一个发现对本阶段很重要。一个产生令人信服的输出但不做令人信服的研究的系统，比一个明显失败的系统更危险，而非更安全。评估必须触及底层主张，而非停留在图表上。

### 沙箱逃逸问题

Sakana 自己的仓库 README 警告：

> 由于本软件的性质——执行 LLM 生成的代码，我们无法保证安全。存在危险包、不受控的网络访问和意外进程生成的风险。使用风险自负，请考虑 Docker 隔离。

这是未验证领域中自主性的操作形态。LLM 编写代码；代码运行；代码可以做进程允许的任何事情。如果没有硬限制文件系统、网络和进程操作的沙箱，任何自主研究代理都可能泄露数据、消耗计算资源或重写自身。

AlphaEvolve 的沙箱故事更容易，因为它的评估器很严格。AI Scientist v2 的循环运行开放式代码和开放式目标。这就是为什么它需要更强的隔离（最低 Docker；推荐 seccomp / gVisor）和在每个投稿离开系统前的手动审查。

### v2 在前沿技术栈中的位置

| 系统 | 目标 | 输出类型 | 评估器 | 已知故障 |
|---|---|---|---|---|
| AlphaEvolve | 算法 | 代码 | 单元 + 基准 | 受评估器严格性约束 |
| DGM | 代理脚手架 | 代码 | SWE-bench | 奖励黑客攻击 |
| AI Scientist v2 | 研究论文 | 文本 + 代码 + 图表 | 同行评审（弱） | 实验失败、错误标记、修饰掩盖弱点 |

v2 的自动评估器在三者中最弱，输出表面最广，到公共产物的路径最短。操作控制（沙箱、审查、披露）承担了大部分安全工作。

## 使用它

`code/main.py` 将 v2 循环模拟为状态机：想法 → 新颖性检查 → 实验 → 图表 → 撰写 → 审查 → 接受或迭代。每个状态都有从 Beel 等人的发现中提取的可配置失败概率。运行模拟器 N 次循环并计数：

- 多少想法到达投稿阶段。
- 多少投稿会有精心修饰的论文所掩盖的关键实验缺陷。
- 重试预算如何在质量和产量之间权衡。

## 交付它

`outputs/skill-ai-scientist-sandbox-review.md` 是研究循环代理产生的任何内容在离开沙箱前的两关审查清单。

## 练习

1. 使用默认参数运行 `code/main.py`。多少比例的循环运行产生"干净"论文？多少比例产生带有图表批评所修饰的实验失败缺陷的论文？

2. 默认值已经使用了 Beel 等人的 42% / 25%。使用 `--experiment-failure 0.20 --novelty-mislabel 0.10` 重新运行，然后使用 `--experiment-failure 0.60 --novelty-mislabel 0.40` 重新运行。两次运行之间"精心修饰但有缺陷"的比例如何变化？

3. 阅读 Sakana 的 AI Scientist v2 仓库 README 中关于沙箱要求的内容。命名两个你会应用于多日自主运行的额外限制（Docker 之外）。

4. 阅读 Beel 等人第 4 节关于展示质量差距的内容。设计一个额外的评估器来捕获看起来精致但实验有缺陷的论文。

5. 提出一个研究代理输出的人类审查协议，比"一个博士阅读每篇论文"更具可扩展性。识别瓶颈并围绕它设计。

## 关键术语

| 术语 | 人们怎么说 | 实际含义 |
|---|---|---|
| AI Scientist v1 | "Sakana 的模板化研究代理" | 在固定脚手架中填充实验 |
| AI Scientist v2 | "无模板研究代理" | 带有 VLM 图表批评的代理树搜索 |
| 代理树搜索 | "分支研究代理" | 并行扩展多个实验计划；通过内部批评者剪枝 |
| 视觉语言批评 | "VLM 对图表的修饰" | 多模态模型读取图表并重写以提高清晰度 |
| 文献检索 | "新颖性检查" | 搜索先前工作以确认想法新颖性——记录有错误标记 |
| 修饰掩盖 | "精美论文，破损研究" | 展示质量超过实验质量；隐藏弱点 |
| 沙箱逃逸 | "LLM 代码突破" | 代理执行的代码做了循环设计者未意图的事情 |
