# RAG 管道核心概念

> 日期: 2026-06-16

## 1. RAG 的本质

RAG（检索增强生成）= **搜索 + 粘贴 + 回答**。在文档存储中检索相关段落，将其粘贴到提示词中，让 LLM 基于这些段落回答。LLM 从闭卷考试变成开卷考试。

核心模式：`查询 → 检索 → 增强提示词 → 生成`

## 2. RAG vs 微调

| 关注点 | 微调 | RAG |
|--------|------|-----|
| 本质 | 永久改变模型权重 | 临时改变模型上下文 |
| 成本 | 每次训练 $1K-$100K+ | 每次查询 $0.01-$0.10 |
| 新鲜度 | 需重新训练 | 重新索引文档几分钟搞定 |
| 可审计性 | 无法追溯来源 | 展示精确检索段落 |
| 幻觉 | 仍会自由产生 | 基于检索文档回答 |

**微调唯一胜出的场景：** 需要模型采用特定风格、语调或推理模式。事实性知识检索，RAG 每次都赢。

## 3. 嵌入与向量相似度

嵌入模型将文本转换为密集向量，语义相似的文本向量相近。三种相似度计算方式：

| 度量方式 | 公式 | 看什么 | 适用场景 |
|----------|------|--------|----------|
| **余弦相似度** | dot(a,b) / (\|\|a\|\| × \|\|b\|\|) | 方向 | RAG 语义搜索（默认） |
| **点积** | Σ(aᵢ × bᵢ) | 方向 + 大小 | 向量已归一化时（等价余弦但更快） |
| **L2 距离** | √(Σ(aᵢ - bᵢ)²) | 绝对距离 | 聚类、异常检测 |

关键洞察：**余弦看方向，点积看方向+力度，L2 看绝对距离。** RAG 用余弦是因为长短文档语义可能一样，需归一化掉大小干扰。

同一方向不同大小的两个向量：余弦 = 1.0（完全相同），点积 ≠ 1.0（受大小影响），L2 ≠ 0（有距离）。

## 4. 分块策略

文档太长不能整体嵌入，必须切片。块大小的选择至关重要：

- **太小（64-128 token）：** 缺乏上下文，"It increased 15%"不知道"it"指什么
- **太大（2048+ token）：** 涵盖多个主题，稀释相关性
- **最佳点（256-512 token）：** 足够自包含，足够聚焦，50 token 重叠

三种分块方法：
- **固定大小分块：** 每 N 个 token 切一刀，加 overlap 防断句
- **语义分块：** 按段落/章节自然边界切
- **递归分块：** 章节 → 段落 → 句子，逐级细化（LangChain 默认方法）

## 5. 完整 RAG 流程（6 步）

```
用户问题 → ① 嵌入查询 → ② 向量搜索 → ③ 返回 top-k → ④ 格式化块 → ⑤ 构建提示词 → ⑥ LLM 生成
```

**① 嵌入查询：** 用户问题通过嵌入模型变为向量。查询和文档块必须用**同一模型、同一词汇表、同一 IDF 权重**。

**② 向量搜索：** 查询向量与向量存储中所有块计算余弦相似度，排序。

**③ 返回 top-k：** 取相似度最高的 k 个块（k 通常 5-10），映射回原始文本。

**④ 格式化块：** 给每条检索结果加 `[Source N]` 标记，便于 LLM 引用出处。

**⑤ 构建提示词：** 系统指令 + 格式化的检索块 + 用户问题 → 完整 prompt。约束 LLM "只基于上下文回答，不知道就说不知道"。

**⑥ LLM 生成：** 将 prompt 喂给 LLM，生成有依据的回答。

## 6. 数据形态变化

| 步骤 | 输入 → 输出 | 形态变化 |
|------|-------------|----------|
| 嵌入查询 | 字符串 → 向量 | 文本 → 数字 |
| 向量搜索 | 查询向量 + 存储向量 → 索引 + 分数 | 数字 → 排序结果 |
| 返回 top-k | 索引 → 文本块 + 分数 | 索引 → 原始文本 |
| 格式化块 | 文本块列表 → 带标记上下文 | 原始文本 → 结构化文本 |
| 构建提示词 | 上下文 + 问题 → 完整 prompt | 结构化文本 → LLM 输入 |
| LLM 生成 | prompt → 最终回答 | prompt → 自然语言 |

## 7. 生产级参数参考

- 每次检索 **k = 5-10** 个块
- 块大小 **256-512 token**，50 token 重叠
- 上下文预算每次查询 **2,500-5,000 token**
- 总提示词 **8,000-16,000 token**
- 检索延迟 **50-200ms**，生成延迟 **500-3000ms**
- 向量数据库小规模用 FAISS/Chroma，生产用 Pinecone/pgvector/Qdrant（底层 HNSW 实现毫秒级检索）

## 8. 迁移到生产环境

课程用 TF-IDF + 暴力搜索教学，迁移到生产只需换两个函数：

- 嵌入函数 → `openai.embeddings.create` 或 Anthropic API
- 生成函数 → `chat.completions.create` 或 `messages.create`
- 向量存储 → ChromaDB 三行代码：`create_collection` → `add` → `query`

检索逻辑、分块、提示词构建——无论使用哪些模型都相同。
