# 嵌入与向量表示学习笔记

> 日期: 2026-06-16

## 1. MTEB 基准

MTEB（Massive Text Embedding Benchmark）是评估嵌入模型的标准跑分平台，涵盖 8 个任务类别：分类、聚类、配对分类、重排序、检索、STS（语义文本相似度）、摘要、双语挖掘。分数越高越好。2026 年主流模型分数在 62-68 之间。benchmark 就是标准化跑分，价值在于可横向比较。

## 2. RAG 命中率

Hit Rate@k 的定义：top-k 检索结果中只要包含正确答案就算击中（1），没有就是 0，对所有查询取平均。计算公式：`Hit Rate@k = 命中查询数 / 总查询数`。是最基础的 RAG 评估指标，先用它判断管道是否基本工作，再用 Precision/Recall/MRR 做细粒度优化。

## 3. 影响 top-k 命中的因素

| 因素 | 影响方式 |
|------|----------|
| **嵌入模型** | 语义捕捉能力直接决定向量质量 |
| **chunk 策略** | 含大小和重叠参数；太大内容稀释，太小丢上下文 |
| **查询质量** | 模糊查询检索效果天然差 |
| **数据预处理** | 脏数据、重复数据拉低精度 |
| **重排序 (reranker)** | bi-encoder 检索后加 cross-encoder 重排能显著提升 |
| **混合搜索** | 语义 + 关键词混合比纯语义稳 |
| **元数据过滤** | 先按来源/类型缩小范围再搜索 |

## 4. Bi-Encoder vs Cross-Encoder

两者是**技术架构**的名字，不是具体模型。同一个模型（如 BERT）可以按两种方式用。

- **Bi-Encoder**：query 和 doc 独立编码成向量，再算相似度。快，文档向量可预计算。
- **Cross-Encoder**：query 和 doc 拼一起输入模型，输出相关性分数。慢但更准，能做交叉注意力。

生产标配：Bi-Encoder 做第一遍快筛（top-100），Cross-Encoder 做第二遍精排（top-10）。

## 5. Matryoshka 嵌入

**核心思想**：训练时修改损失函数，让前 N 个维度包含最重要的信息，像俄罗斯套娃——大娃娃套小娃娃，每层都完整。

**为什么需要改训练目标**：不改的话模型没有动机把重要信息放前几个维度，直接截断等于随机扔信息。改了损失函数后，训练时同时计算完整和截断向量的 loss，逼模型学会"前面放最重要的"。

**核心价值**：1536 维截断到 256 维，存储减少 6 倍，accuracy 只掉 3-5%。

**与量化的区别**：
- Matryoshka：砍**维度数**（1536→256），每个值还是 float
- 量化：砍**每个值的精度**（float32→int8），维度不变
- 两者可叠加：Matryoshka 截断 + 量化，存储压到 1/48

**主流程度**：2026 年大部分生产级嵌入模型都支持 Matryoshka（OpenAI、Google、Cohere、Voyage、Qwen、Nomic 等）。

## 6. 嵌入模型的主流应用

嵌入模型不只是 LLM 的"持久记忆"，而是**外部检索层**。主要场景：

| 应用 | 怎么用嵌入 |
|------|-----------|
| RAG | 检索相关文档喂给 LLM，扩展上下文 |
| 语义搜索 | 用含义匹配代替关键词匹配 |
| 推荐系统 | 找相似物品/内容 |
| 聚类/分类 | 用向量做无监督分组或作为分类器特征 |
| 去重/近似检测 | 找重复或近似内容 |
| 异常检测 | 离群向量 = 异常 |

RAG 中的"持久记忆"只是 RAG 的一个子集——把用户历史、对话记录等持久化到向量数据库，需要时检索回来。
